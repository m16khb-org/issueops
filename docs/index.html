Team memory for coding agents, shipped in the same PR as the code.

IssueOps is a local agent harness. When an agent hits a pitfall or makes a design decision, it writes a record into the repository with the change. The next agent on your team reads it before related work.

    01 / record

    Pitfalls and decisions become files, reviewed with the code

    A caution records a pitfall and its fix. An ADR records a design decision. Both are plain Markdown under .issueops/. These are real records from this repository; pick a field to see what it carries.

      02 / route

      The next task gets the right records first

      Before work starts, route-docs picks up to five past records that share at least two terms with the task. Type a task and watch it choose.

        03 / enforce

        Gates, not good intentions

        Records are written inside a ten-stage cycle. The docs verdict is bound to the change set, so a PR cannot ship knowledge that is out of date. Try to publish before recording the verdict, or change the diff after it.

          05 / compare

          How this differs from AGENTS.md and agent memory

          IssueOps does not replace AGENTS.md. Rules every session needs stay there; pitfalls and decisions that matter only for some tasks become records.

          06 / install

          Build from source

          You need Git, Go 1.26.6 or later, and at least one supported host. There is no public binary release yet.

          install.sh
          $ git clone https://github.com/m16khb-org/issueops.git
$ cd issueops
$ ./install.sh --dry-run --json   # review the plan first
$ ./install.sh
$ ./bin/issueops doctor --repo . --json

          Then ask your agent: "Use issueops to fix the login error. Reproduce it with an expired session and add a test. Go as far as opening a draft PR." Skills and issue/PR templates are currently Korean. See the full README.
