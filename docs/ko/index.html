코딩 에이전트가 배운 것을 코드와 같은 PR에 남기는 팀의 기억

IssueOps는 로컬 에이전트 하네스입니다. 에이전트가 함정을 만나거나 설계 결정을 내리면 그 내용을 변경과 함께 저장소에 기록합니다. 팀의 다음 에이전트는 관련 작업을 시작하기 전에 그 기록을 읽습니다.

    01 / record

    함정과 결정을 파일로 남기고 코드와 함께 리뷰합니다

    caution은 함정과 해결 방법을, ADR은 설계 결정을 기록합니다. 둘 다 .issueops/ 아래의 마크다운 파일입니다. 오른쪽은 이 저장소의 실제 기록입니다. 항목을 누르면 그 항목이 담는 내용을 보여 줍니다.

      실제 기록

      02 / route

      다음 작업에는 맞는 기록을 먼저 건넵니다

      작업을 시작하기 전에 route-docs가 작업 설명과 단어가 두 개 이상 겹치는 과거 기록을 최대 다섯 건 고릅니다. 작업을 입력해서 어떤 기록이 골라지는지 확인해 보세요.

      예시:
        route-docs의 기록 선택 규칙을 브라우저에서 그대로 실행합니다. 대상은 이 저장소의 caution·ADR 기록 172건입니다(2026-11-03 기준). 드물게 쓰이는 단어일수록 점수가 높습니다. 겹치는 단어 하나마다 ln(N/df)를 더합니다.

        03 / enforce

        기억에 맡기지 않고 게이트로 막습니다

        기록은 10단계 사이클 안에서 작성합니다. 문서 반영 판정은 변경 집합에 묶이기 때문에, 오래된 기록을 담은 PR은 발행되지 않습니다. 판정 전에 발행하거나, 판정 뒤에 diff를 바꿔 보세요.

          05 / compare

          AGENTS.md, 에이전트 메모리와 무엇이 다른가

          06 / install

          소스에서 빌드합니다

          Git, Go 1.26.6 이상, 사용할 코딩 호스트 하나 이상이 필요합니다. 아직 공개된 바이너리 릴리스는 없습니다.

          install.sh
          $ git clone https://github.com/m16khb-org/issueops.git
$ cd issueops
$ ./install.sh --dry-run --json   # 설치 계획을 먼저 확인합니다
$ ./install.sh
$ ./bin/issueops doctor --repo . --json

          설치한 뒤 에이전트에게 이렇게 요청합니다. "issueops로 로그인 오류를 고쳐 줘. 만료된 세션으로 재현하고 테스트를 추가해. draft PR 생성까지 진행해." 자세한 내용은 전체 README에 있습니다.
