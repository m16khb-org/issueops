# IssueOps project-doc gates: link-plan checks the four plan sections and no-change needs reviewed docs

- Date: 2026-09-08
- Kind: `adr`
- Source: cli
- Summary: The plan stage's document check and the docs stage's no-change verdict were skill-text only; both now fail closed in the CLI, and the project_docs_review gate no longer skips records without an execution lease.
- Context: An audit on 2026-09-08 found three soft spots in the project-doc flow. (1) issueops-plan requires the plan to carry '## 적용되는 결정과 주의사항' and three sibling sections, but issueops link-plan accepted any file, so a plan that never recorded which documents were read could enter implement. (2) project-docs-review record --verdict no-change only required a non-empty free-text --evidence, so the code could not tell 'compared and found nothing' from 'did not compare'. (3) projectDocsReviewMissing returned '' when record.Execution was nil, silently skipping the docs gate for cycles that reached post-implement phases without a lease. AGENT_WORKFLOW's during-work append rule and the docs stage's after-clean rule also did not reference each other.
- Decision: (1) issueops link-plan reads the plan and rejects it with 'plan is missing required sections: ...' unless all four titles in issueopsdomain.RequiredPlanSections are present as '## ' headings; the check runs only for a fresh link, after the already-linked identity rule, so re-linking the same plan stays idempotent. (2) project-docs-review record gains a repeatable --reviewed-doc PATH; --verdict no-change requires at least one, and every reviewed path must resolve inside the worktree, live under .issueops/ or be the root AGENTS.md, and exist as a file. The record stores them as reviewed_docs. --verdict updated may carry reviewed docs under the same rule. (3) projectDocsReviewMissing drops the Execution == nil early return; the gate now applies to every record from implement onward. (4) AGENT_WORKFLOW Work/Finish and skills/issueops-docs point at each other: appends during implement precede the clean seal and stand, appends after the clean seal are re-sealed by the docs stage, appends after verify make both seals stale and next returns to docs. Hooks stay context-only; every new enforcement lives in the CLI gate, per the 2026-08-27 decision.
- Consequences: Plans written before this change that lack the four headings cannot be linked until the headings are added; cycles with an already-linked plan are unaffected. Scripts and prompts that record no-change must pass --reviewed-doc; the owner prompt template, owner command catalog, usage golden, and command parser carry the flag. Cycles without an execution lease that sit in post-implement phases now report project_docs_review as missing. Test fixtures now write plans through planBodyForTest and commit .issueops/CAUTIONS.md into the base repo so the no-change helper has a real document to cite. Evidence: internal/domain/issueops/plan_sections.go, internal/adapter/issueops/linking/link.go, internal/adapter/issueops/issueops_project_docs_review.go, cmd/issueops/issueopscli/issueops_subcommands.go, go test ./internal/adapter/issueops/... ./cmd/issueops/issueopscli/.
