# Remove the Orca integration and execution mode selection

- Date: 2026-10-15
- Kind: `adr`
- Source: cli
- Summary: 실행 방식은 direct(git sibling worktree와 generation-fenced lease) 하나뿐이다. Orca 연동과 실행 방식 선택(auto/direct/orca), 실행 기록의 mode·selection·driver 필드, `execution resume`·`execution switch-mode`, owner 프롬프트와 context packet을 지운다. 세션 인계는 release, `execution replace`, `claim --claim-current-token`으로 이어지는 기존 인수 체인만 쓴다.
- Context: `execution prepare --mode auto`는 Orca가 준비되어 있으면 Orca를, 아니면 direct를 골랐다. 그 대가로 실행 기록에 mode·selection·driver·readiness 지문·owner 컨텍스트가 붙었고, 이슈 본문과 context packet의 digest, owner 프롬프트 템플릿, Orca 터미널 정리, `resume`, `switch-mode`가 함께 따라왔다. 두 방식이 같은 lease 규칙을 따르는데도 준비·복구·정리 경로가 방식마다 갈라졌고, 그 갈래마다 golden과 caution이 따로 필요했다.
- Decision: 1) 실행 방식은 direct 하나다. mode·selection·driver 필드와 실행 방식 메뉴를 지운다. 2) `execution prepare`는 `issueops execution prepare --id ID $ACTOR_FLAGS [--confirm] [--json]` 하나다. preview가 workspace root·branch·base를 보여 주고 `--confirm`이 worktree를 만든다. `--mode`, `--direct-reason`, `--owner-host`, `--owner-model`, `--owner-effort`, `--issue-snapshot-file`, `--expected-readiness-fingerprint`를 지운다. 3) `execution claim`에서 `--issue-body-sha256`, `--context-packet-sha256`, `--issue-snapshot-file`을 지우고 `--claim-current-token`은 유지한다. `execution replace`와 `reconcile`에서도 `--issue-snapshot-file`을 지운다. 4) `execution resume`, `execution switch-mode`, MCP `issueops_execution`의 `resume` action, `doctor --preserve-terminal`, `doctor --sealed`, `interactive` doctor profile을 지운다. `--preserve-cycle`은 유지한다. 5) cleanup finish의 `orca_remove` 단계, abandon의 `orca_resources_absent` 게이트, Orca 터미널 처리를 지운다. 워크트리 프로세스 정지(`workspace_processes_stop`)는 유지한다. 6) 세션 인계는 기존 세션이 `release`로 lease를 해제하고, 새 세션이 자기 native actor로 `execution replace --id ID --expected-generation N --preview`를 실행해 반환된 `--reseed` 명령을 따른 뒤 `claim --claim-current-token`을 실행하는 체인만 쓴다. `next`는 claimable이면 `claim --claim-current-token`, released이면 `replace --preview`, revoking이면 `replace --finalize-preview`로 안내한다. 7) 자동 세션 선택은 브랜치와 worktree를 준비한 뒤 Herdr를 확인한다. Herdr 세션에서 준비 중이고 실행 중인 서버, 호환성, 현재 native host 실행 가능 여부가 확인되면 같은 worktree의 새 Herdr 세션으로 인계한다. 그렇지 않으면 현재 세션에서 이어가거나 사용자가 직접 연 두 번째 터미널에서 수동으로 인계한다. 바이너리 설치 여부만으로 ready라 판단하지 않고 런처를 설치하거나 서버를 시작하지 않는다. cmux는 명시 선택일 때만 쓰며 `execution handoff-cmux`는 그대로 둔다. 8) handoff-delivery 관측 launcher는 `direct`, `herdr`, `cmux`만 남긴다. 9) Orca owner 프롬프트 템플릿, owner context packet, `issueops-v1-owner-execution-v1.md` 프롬프트 문서를 지운다.
- Supersedes: [2026-09-05 ten-stage skills](2026-09-05-issueops-ten-stage-skills-with-auto-execution-mode.md)의 `execution prepare --mode auto`가 Orca가 준비되어 있으면 Orca를, 아니면 direct를 고른다는 결정과, 같은 문서의 거절 대안 "Make release + reseed the normal way to move a cycle between sessions"를 대체한다. 이제 release와 reseed 체인이 세션 사이의 유일한 정상 인계 경로다. 같은 문서의 열 단계 구조, `issueops next`, planning-before-worktree 순서는 그대로다. [2026-07-19 operational-health](2026-07-19-operational-health-authority-and-external-reconciliation.md)에서 `doctor`가 선택적 Orca를 포함해 판정한다는 부분도 대체한다. `doctor`는 Git, IssueOps, user-state 정합성만 판정한다. [2026-07-15 supervised handoff](2026-07-15-supervised-handoff-coordinator-isolation.md)의 Orca terminal handle routing metadata 부분, [2026-07-24 planner/implementer](2026-07-24-issueops-planner-implementer-dual-structure.md)의 Orca owner packet 봉인과 orca→git 정리 순서 부분, [2026-07-26 linked branches](2026-07-26-linked-branches-pinned-to-sealed-base-sha.md)의 "Orca prepare before remote linking" 순서, [2026-10-08 role models](2026-10-08-role-models-resolve-from-global-and-local-settings-and-are-i.md)의 Orca owner 세션 주입 부분도 대체한다. 네 문서의 나머지 결정(coordinator 격리, 이원 구조와 구현 리뷰 publication 게이트, sealed base SHA 고정, role model 해석)은 그대로다.
- Consequences: 1) 옛 바이너리가 쓴 실행 기록(mode·selection·driver 포함)은 새 바이너리가 읽지 못한다. 해당 cycle은 새 바이너리에서 prepare, abandon, finish 어느 것도 할 수 없으므로 업데이트 전에 옛 바이너리로 `cleanup finish`나 `cleanup abandon`을 끝내야 한다. 옛 모양 실행 기록이 state에 하나라도 남아 있으면 새 바이너리에서는 다른 모든 cycle의 `execution prepare`도 `invalid state`로 실패하고 `doctor`가 `issueops_read_failed`를 보고한다. 이 기록을 치우는 명령은 이번 범위에 없다(후속 작업). 2) handoff-delivery 감사 파일의 orca launcher 줄도 새 바이너리에서 읽히지 않는다. 이 기기에서는 그 줄이 남아 있는 동안 cmux 인계(`execution handoff-cmux`)가 막히고, 감사 파일을 정리한 뒤에 다시 열린다. 같은 이유로 claim 직후 manual owner-claim 관측(best-effort)도 조용히 빠진다. 3) 롤백으로 PR을 되돌린 옛 바이너리는 새 바이너리가 쓴 실행 기록을 읽지 못한다. 옛 검증기가 mode·selection·driver를 요구하기 때문이다. 4) 저장소 밖 호출자(전역 스킬, 스크립트)가 `--mode direct --direct-reason`, `execution resume`, `doctor --sealed`, `doctor --preserve-terminal`을 부르면 업데이트 직후 실패한다. 새 형태는 `issueops execution prepare --id ID $ACTOR_FLAGS [--confirm]`이고, 세션 인계는 `release`, `execution replace --preview`, `claim --claim-current-token` 순서다. 5) `execution ... --issue-snapshot-file`, `--issue-body-sha256`, `--context-packet-sha256`을 넘기던 호출자도 같은 방식으로 실패한다. 6) 로컬 state에 남은 옛 모양 데이터의 정리는 이번 변경에 넣지 않고 후속 작업으로 둔다.
- Non-goals: cmux 제거, Herdr 연동 코드를 Go로 옮기는 일, 로컬 state의 옛 데이터 정리.
- Alternatives / rejected options:
  - Orca를 optional 확장으로 남기고 기본값만 direct로 바꾼다 — rejected: mode·selection·driver 필드와 두 갈래의 복구·정리 경로가 그대로 남아, 지우려던 복잡도가 줄지 않는다.
  - `execution resume`을 인수 체인의 별칭으로 남긴다 — rejected: 같은 일을 하는 명령이 둘이 되어 next 라우팅과 audit이 갈라진다.
  - 옛 실행 기록을 읽을 때 mode·selection·driver를 무시하는 호환 reader를 둔다 — rejected: [2026-10-07 decision](2026-10-07-readers-accept-only-the-current-record-shape.md)이 읽기 경로의 숨은 호환 동작을 금지한다.
