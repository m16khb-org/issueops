# Continue CLI configuration and telemetry: bounded evidence lane

**Retrieved:** 2026-10-02
**Scope:** Continue public CLI configuration, telemetry, releases, and IssueOps applicability. Sources were fetched directly; no installs or external mutations were performed.

## Findings

1. **The current published `cn` CLI supports layered, session-aware configuration.** The official guide says resolution order is `--config` path, saved last-used config, then `~/.continue/config.yaml`; a launch flag overrides saved choice for that session. `/config` switches local configs and persists selection. The CLI guide says YAML is shared with Continue IDE extensions, rules and agents accept repeatable flags, and secrets can be environment-backed. npm lists `@continuedev/cli` latest as **1.5.47**, whose `gitHead` commit is dated **2026-06-18**. GitHub lists **v2.1.0-vscode**, a prerelease published **2026-06-19**, newer than stable v2.0.0-vscode from the same date. These are different release tracks; the extension tag is not the CLI package version. No retrieved official release evidence falls within the preceding 90 days, so the window was widened to the latest available artifacts. **Certainty: high** for the documented behavior and registry tag; **medium** for latest-at-retrieval status because GitHub and npm are publisher-controlled. **Applicability:** per-run config selection is relevant, but IssueOps deliberately reloads workspace overrides each evaluation; persistent last-used selection would be a poor fit for policy state.
   Sources: [CLI configuration](https://docs.continue.dev/cli/configuration); [CLI guide source](https://github.com/continuedev/continue/blob/main/docs/guides/cli.mdx); [npm package metadata](https://registry.npmjs.org/@continuedev/cli/1.5.47); [package source commit, dated 2026-06-18](https://api.github.com/repos/continuedev/continue/commits/d3f60ba9dd3fb5bfd3c91d6fbb41ce1aa768db45); [v2.1.0-vscode release API](https://api.github.com/repos/continuedev/continue/releases/tags/v2.1.0-vscode).

2. **The CLI exposes an automation-friendly observation surface without its TUI.** Official docs document `cn -p`, `--format json`, `--silent`, saved sessions and `cn ls --json`; the CLI guide documents `--verbose` logs at `~/.continue/logs/cn.log`. Headless mode excludes tools needing interactive approval unless explicitly allowed. **Certainty: high, first-party docs. Applicability:** IssueOps already has JSON contracts and read-only `review-metrics`; this is precedent for structured output plus local diagnostics, not for adding another session store or loosening policy.
   Sources: [CLI guide source](https://github.com/continuedev/continue/blob/main/docs/guides/cli.mdx); [headless mode](https://docs.continue.dev/cli/headless-mode); [configuration and troubleshooting](https://docs.continue.dev/cli/configuration).

3. **The CLI telemetry implementation requires exporter configuration and environment controls; it is not an unconditional network sender.** In the package source commit, telemetry starts only when enabled and an OTEL exporter variable is present. `CONTINUE_METRICS_ENABLED=0` disables it; `=1` enables it, otherwise `CONTINUE_CLI_ENABLE_TELEMETRY=0` disables it. Exporters include console or OTLP, with configurable OTLP endpoint/headers. Defined counters and histograms cover sessions, code changes, commits, tokens, cost, startup and response time. **Certainty: high for this source snapshot; runtime deployment defaults lack independent corroboration. Applicability:** Continue's exporter pattern and metrics vocabulary could inform visibility, but IssueOps already records external-LLM usage and web-fetch latency; require a concrete gap before duplicating telemetry.
   Sources: [telemetry service at package `gitHead`](https://github.com/continuedev/continue/blob/d3f60ba9dd3fb5bfd3c91d6fbb41ce1aa768db45/extensions/cli/src/telemetry/telemetryService.ts); [package metadata and `gitHead`](https://registry.npmjs.org/@continuedev/cli/1.5.47).

4. **“Telemetry removed” and CLI OTEL instrumentation describe different scopes.** Continue's README says the final 2.0.0 release removed *anonymous telemetry* and authentication across products. The offline guide's “Allow Anonymous Telemetry” setting specifically tells VS Code users to disable PostHog requests. Separately, the CLI has configurable OTEL metrics gated by exporter-related environment configuration. The official `docs.continue.dev/reference/telemetry` returned 404, so the older IDE preference could not be checked against a current reference. The README and CLI source are first-party, not independent corroboration; npm metadata corroborates the package artifact/version, not telemetry semantics. **Certainty: high** that the docs describe distinct scopes; **medium** on the exact historical boundary of anonymous-telemetry removal. **Counterevidence:** `logUserPrompt` and related methods exist, but OTLP log export is marked TODO; this does not prove prompt transmission.
   Sources: [Continue README](https://github.com/continuedev/continue/blob/main/README.md#final-200-release); [offline guide](https://docs.continue.dev/guides/running-continue-without-internet); [CLI telemetry source](https://github.com/continuedev/continue/blob/d3f60ba9dd3fb5bfd3c91d6fbb41ce1aa768db45/extensions/cli/src/telemetry/telemetryService.ts).

## IssueOps fit and limits

The project favors measured bottlenecks over speculative caching (`.issueops/CONSTITUTION.md:52-56`), derives review rounds, verdicts, regressions and stage durations through read-only `issueops review-metrics` (`.issueops/CONVENTIONS.md:84-85`), and keeps default SessionStart hooks context-only (`.issueops/AGENT_WORKFLOW.md:66-68`). The external-LLM usage ADR records provider/model/tokens/duration best-effort and defers enforcement until baselines accumulate (`.issueops/adr/decisions/2026-07-02-external-llm-usage-observation.md:7-11`); the loop ADR rejects speculative token/cost enforcement (`.issueops/adr/decisions/2026-07-09-loop-contracts.md:18-21`). Continue offers config and metric precedents, not evidence for an IssueOps dependency or any speedup. No independent third-party corroboration was used; npm corroborates only the publisher's package artifact/version.
