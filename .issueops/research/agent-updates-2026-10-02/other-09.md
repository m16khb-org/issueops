# Goose extensions, sessions, and scheduling

**Retrieved:** 2026-10-02
**Scope:** One bounded evidence lane supporting IssueOps performance, optimization, and visibility. Official Goose release notes/docs and this repository only. No installs or external mutations.

## Findings

1. **Latest release observed: Goose v1.52.0, published 2026-09-23.** The official release page lists v1.52.0 above v1.51.0 (2026-09-17). v1.52.0 includes “Split extension transports out of ExtensionManager”; the linked PR describes routing stdio, builtin, and Streamable HTTP configs through separate connection modules, consolidating protocol retry logic, and reusing resolved extension configuration rather than resolving environment/secrets repeatedly. This is a concrete maintainability/setup-path change, not a published latency result. **Certainty: high** for version/date and described change; **medium** that it improves performance (no measurements). **Applicability:** profile IssueOps host/extension startup before considering similar factoring or reduced repeat work. **Counterevidence:** release notes and PR are first-party and provide no benchmark; the PR notes a regression in initial refactoring that passed a Docker setting to remote HTTP clients, illustrating that boundary simplification needs transport-specific tests. Sources: [v1.52.0 release notes](https://github.com/aaif-goose/goose/releases/tag/v1.52.0); [PR #12088](https://github.com/aaif-goose/goose/pull/12088); [v1.52.0 published_at API record](https://api.github.com/repos/aaif-goose/goose/releases/394774549).

2. **Scheduled work is represented as reusable recipes with inspectable run sessions.** Current official docs describe recipes with instructions, optional model/provider, parameters, extensions, and structured output; a schedule selects a recipe, foreground/background execution mode, and cron-derived frequency. The Scheduler view exposes last-run details, manual run, pause/edit actions, and sessions created by that schedule. CLI commands include `schedule list`, `run-now`, and `sessions`; `schedule add` copies the recipe into `~/.local/share/goose/scheduled_recipes`. v1.51.0 (2026-09-17) records scheduler fixes for recipe validation and guarding recipe-before-inference ordering; v1.52.0 (2026-09-23) fixes duplicate schedules overwriting recipes. **Certainty: high** for documented interface and listed release fixes. **Applicability:** useful precedent for tying repeatable runs to explicit inputs and inspectable per-run records; IssueOps should measure repeatable verification steps before adding a scheduler-like surface. **Counterevidence:** this is Goose product behavior, not evidence that scheduled execution is faster or more reliable; release notes do not quantify the fixes. Sources: [recipes and scheduling docs](https://goose-docs.ai/docs/guides/recipes/session-recipes/); [CLI schedule docs](https://goose-docs.ai/docs/guides/goose-cli-commands/); [v1.51.0 notes](https://github.com/aaif-goose/goose/releases/tag/v1.51.0); [v1.52.0 notes](https://github.com/aaif-goose/goose/releases/tag/v1.52.0).

3. **Extensions can be scoped to a session instead of globally enabled.** The official extension guide says defaults affect future sessions, not active ones; mid-session changes affect only that chat. CLI startup accepts named stdio, Streamable HTTP, and builtin extensions. v1.52.0 includes a fix to start a chat without extensions when none are selected and requires recipe consent before `session/new` starts recipe extensions. **Certainty: high** for documented scope and release entries. **Applicability:** IssueOps can treat per-run tool selection as a candidate for reducing unnecessary capability setup while preserving global defaults; evaluate only with startup-time and behavior measurements. **Counterevidence:** Goose publishes no cost or latency comparison between narrow and broad extension sets, and omitting tools may make a task fail or require another run. Sources: [Using Extensions](https://goose-docs.ai/docs/getting-started/using-extensions/); [v1.52.0 notes](https://github.com/aaif-goose/goose/releases/tag/v1.52.0); [recipe-consent PR #12094](https://github.com/aaif-goose/goose/pull/12094).

4. **Session records and logs expose operational evidence, but also contain sensitive material.** Goose’s official logging guide says SQLite session records include IDs/names, working directory, timestamps, messages, tool calls/results, token usage, and extension data/configuration. CLI logs include extension initialization, capabilities, results, errors, and timestamps; dated CLI/server log directories are cleaned after two weeks. The CLI also documents JSON session listing and session diagnostics, whose output contains full messages and logs. **Certainty: high** for the documented fields and retention behavior, but they are product docs rather than an independent audit. **Applicability:** aligns with IssueOps’ existing read-only `review-metrics` and self-augment per-step duration summaries (`internal/domain/issueops/review_metrics.go:11-39`; `internal/contract/selfaugment/history_summary_types.go:8-43`): prefer derived, bounded metrics over retaining raw transcript-like data. **Counterevidence:** Goose does not document a normalized performance dashboard here; diagnostics can expose credentials, personal data, or proprietary code, so raw session export is not a safe default. Sources: [Goose logs and session storage](https://goose-docs.ai/docs/guides/logs/); [CLI session commands and diagnostics](https://goose-docs.ai/docs/guides/goose-cli-commands/).

## Source independence and IssueOps fit

Release pages, PRs, and goose-docs.ai are all official Goose sources. GitHub’s release API independently confirms the publication timestamp as a separate retrieval surface, but it is still publisher-controlled metadata—not independent corroboration of product behavior. No independent third-party reproduction of a Goose performance result was found. No performance percentage or measured speedup is asserted. The local anchors show IssueOps already derives lifecycle metrics without mutating records and summarizes per-label duration distributions; the relevant opportunity is comparing measurable gaps, not duplicating those facilities.
