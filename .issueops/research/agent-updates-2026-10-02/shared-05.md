# Anthropic prompt caching: pricing, sharing, and invalidation

**Retrieved:** 2026-10-02
**Scope:** One bounded evidence lane for IssueOps performance, optimization, and visibility.
**Evidence standard:** Anthropic docs, pricing, and newsroom are official first-party sources from one publisher, not independent corroboration. No independent replication or benchmark is cited. The official GA announcement is dated 2024-12-17; current documentation exposes no revision or cache API version. Findings describe sources fetched on the retrieval date, not anticipated releases.

## Findings

1. **Cache economics depend on writes, reads, TTL, and model.** Anthropic charges 1.25× base input price for a 5-minute write, 2× for a 1-hour write, and ordinarily 0.1× for cache reads/refreshes. Its stated break-even is one read for a 5-minute write and two for a 1-hour write. Exceptions: reads are 0.05× on Opus 5.5 and 0.025× on Fable 5.1/Mythos 5.1. The current table is model-specific; it says Sonnet 5’s $2/$10 input/output rates became standard after the planned 2026-09-01 increase was cancelled. Breakpoint markers add no charge. **Certainty: high, official single-source. Applicability: medium** only if IssueOps later sends repeated prefixes to Anthropic. **Counterevidence:** rates do not establish IssueOps savings; workload, hit rate, model, and stable-prefix size matter. Sources: [Prompt caching pricing](https://platform.claude.com/docs/en/about-claude/pricing#prompt-caching); [guide, pricing](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#pricing), retrieved 2026-10-02.

2. **“Shared” means workspace-scoped on first-party surfaces, not universally organization-wide.** Anthropic says caches are isolated per workspace on Claude API, Claude Platform on AWS, and Microsoft Foundry; Bedrock and Google Cloud use organization-level isolation. The prompt-caching feature reached Claude API general availability on **2024-12-17**; that dated announcement does not corroborate today’s isolation matrix. **Certainty: high, official single-source. Applicability: medium** for future workspace/provider comparisons, not evidence IssueOps uses Anthropic. **Counterevidence:** organization-level isolation still does not guarantee a hit without a matching prefix and live TTL. Sources: [Cache storage and sharing](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#cache-storage-and-sharing); [GA announcement](https://www.anthropic.com/news/prompt-caching).

3. **TTL and request ordering constrain reuse.** Default lifetime is five minutes; one hour costs 2× base input for writes. Expiry starts at request start, so generation/streaming consumes TTL. A new entry is available only after the first response begins; parallel cold requests cannot assume mutual reuse. **Certainty: high, official single-source. Applicability: medium** for repeated sequential calls; long generation or concurrent fan-out reduces reuse opportunity. **Counterevidence:** one-hour TTL covers longer workflows, but the higher write price still requires enough reads. Sources: [TTL and pricing](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#pricing); [concurrency and cache thresholds](https://platform.claude.com/docs/en/build-with-claude/prompt-caching); [extended caching announcement](https://www.anthropic.com/news/agent-capabilities-api).

4. **Invalidation is prefix-based; put variable content after a stable breakpoint.** The prefix hierarchy is `tools → system → messages`; changing tool definitions invalidates all levels, while later changes invalidate that level and subsequent ones. A changing timestamp before the breakpoint changes the cumulative hash and can force a write each request. The guide recommends breaking at the last identical block. Lookup checks at most 20 positions per breakpoint, missing older writes. **Certainty: high, official single-source. Applicability: medium** as a design constraint, not proof of IssueOps savings. **Counterevidence:** `tool_choice` changes affect messages only, and mid-conversation system-message behavior varies by model. Sources: [Invalidation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#what-invalidates-the-cache); [prefix matching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

## EXPAND

- If Anthropic direct support becomes a real caller, inspect its response usage fields for cache creation/read tokens and record them per call/model/workspace before proposing a caching optimization; current IssueOps provider evidence gives no Anthropic cache-hit baseline.
- For repeated API workloads, measure exact stable-prefix size, dynamic-prefix changes, elapsed time from request start, cache reads/writes, and TTL/model pricing. This determines observed break-even rather than importing Anthropic’s generic examples.
- **Release-history lead:** the current guide is undated and no versioned caching API is identified here. Compare its invalidation matrix against Anthropic’s dated release notes before treating future behavior changes as a stable contract.
