# OpenCode release, provider, plugin, and MCP evidence

Retrieved: 2026-10-02
Scope: Public official OpenCode sources and the IssueOps repository. This is one bounded evidence lane, not a performance benchmark.

## Findings

1. **Current release evidence favors reliability and observability work, not claimed speedups.** The latest public GitHub release retrieved was **v1.18.34, published 2026-09-30**. Its official notes list session/parent-session identity headers, macOS signing fixes, and signed CLI release binaries. The previous **v1.18.33, published 2026-09-28**, reports honoring Cloudflare AI Gateway response/stream timeouts, surfacing immediate MCP browser-launch failures, and redacting credentials/sensitive headers in debug configuration output. These are concrete reliability and diagnostic improvements; neither release claims a measured performance gain. **Certainty: high** for versions, dates, and notes (official release metadata/notes); **single-source** for what changed, with no independent corroboration used. **IssueOps applicability:** favor bounded timeout handling and actionable diagnostics in operational surfaces; do not infer latency improvements. **Counterevidence:** release notes do not show that these fixes improved throughput or apply to IssueOps. Sources: [v1.18.34 release](https://github.com/anomalyco/opencode/releases/tag/v1.18.34), [v1.18.34 published metadata](https://api.github.com/repos/anomalyco/opencode/releases/tags/v1.18.34), [v1.18.33 release](https://github.com/anomalyco/opencode/releases/tag/v1.18.33), [v1.18.33 published metadata](https://api.github.com/repos/anomalyco/opencode/releases/tags/v1.18.33).

2. **Provider configuration exposes explicit controls relevant to measured optimization.** Official provider/config docs describe more than 75 providers, custom base URLs and model allow/deny lists. Config also documents request, header, and streamed-chunk timeouts (defaults of five minutes), plus `small_model` for lightweight tasks such as title generation. v1.18.33 specifically says Cloudflare AI Gateway now honors response and stream timeouts. This supports separating slow/non-streaming setup from stalled streams and assigning cheaper models to lightweight work as hypotheses to benchmark. **Certainty: high** that these settings/features are documented; **single-source** for provider breadth and intended use. **IssueOps applicability:** inspect existing command/runtime bottlenecks first, then test timeout and model-selection policies only if LLM calls are on the measured hot path. **Counterevidence:** provider count and configurable timeouts are not evidence of IssueOps bottlenecks or cost/latency reductions. Sources: [Providers](https://opencode.ai/docs/providers/), [Config: models and provider timeouts](https://opencode.ai/docs/config/), [v1.18.33 release](https://github.com/anomalyco/opencode/releases/tag/v1.18.33).

3. **MCP tool exposure has an explicit context-cost warning and selective enablement controls.** OpenCode’s MCP docs state that MCP tools add context and that servers with many tools (GitHub MCP is the example) can consume many tokens or exceed context limits. They document disabling servers/tools globally and enabling matching MCP tools per agent; local and remote servers have a configurable tool-fetch timeout defaulting to 5,000 ms. **Certainty: high** for documented behavior and options; **single-source** (official documentation only). **IssueOps applicability:** this aligns with the local guidance to prefer bounded task-specific tools and resources for reusable context (`.issueops/architecture/runtime.md`, “MCP tool design guidance”). Consider measuring tool count/description size and routing optional tools only to the agents that need them. **Counterevidence:** the docs quantify no token savings, and IssueOps already has deterministic, task-specific MCP contracts; do not assume its tool surface is oversized. Source: [MCP servers](https://opencode.ai/docs/mcp-servers/).

4. **Plugin hooks offer an optional visibility path while adding sequential hook and startup-install work.** Official plugin docs expose session, tool, file, LSP, and error-related events, structured `client.app.log()` levels, and event examples; npm plugins are installed with Bun at startup and cached, and hooks from configured sources run sequentially. **Certainty: high** for the documented API and loading behavior; **single-source**. **IssueOps applicability:** event-aligned structured telemetry could help diagnose session/tool behavior when an existing observable boundary is insufficient, but IssueOps should keep core behavior in Go and avoid making an external plugin a readiness dependency, consistent with `.issueops/TECH_STACK.md` (“Core independence”). **Counterevidence:** docs do not establish plugin overhead, log completeness, or performance; sequential hooks could add overhead. Source: [Plugins](https://opencode.ai/docs/plugins/).

## EXPAND

- Measure MCP tool descriptions/count and actual prompt-token impact for representative IssueOps tasks; current official docs warn of context growth but supply no measurements.
- If LLM latency is a measured bottleneck, benchmark lightweight-model routing and provider timeout behavior against the current workflow; do not treat configurable options as performance results.
- Investigate plugin/event telemetry only if a concrete visibility gap remains after checking existing IssueOps diagnostics and structured logs. No independent OpenCode source corroboration was established in this bounded lane.

## Retrieval and limitations

Release dates above are UTC `published_at` values from GitHub’s official release API; the latest release index and version-specific release notes were fetched. All cited public URLs were reopened during verification. An attempted official observability documentation URL, `https://opencode.ai/docs/observability/`, returned HTTP 404 and is not used as evidence. No performance percentages or independent source claims are made.
