# Claude Agent SDK lifecycle and structured results

Retrieved: 2026-10-02
Scope: Public Anthropic Agent SDK docs and releases checked against this repository; this report does not propose adding the SDK.

## Findings

1. **Session reuse is explicit and differs by SDK.** Python `query()` starts fresh unless continued or resumed; `ClaudeSDKClient` retains a session across queries. TypeScript `query()` uses `continue` or `resume`. Sessions preserve conversation history, not filesystem state, so resume is not workspace isolation. An external `SessionStore` enables cross-host resume. **Applicability:** reuse context only for related follow-up work; keep IssueOps worktree and generation ownership separate. **Counterevidence:** transcript mirroring adds storage obligations and cross-host resume requires matching `cwd`. **Certainty: high; official single-source documentation.** Sources: [Python SDK reference](https://docs.anthropic.com/en/docs/claude-code/sdk/sdk-python#choosing-between-query-and-claudesdkclient); [session guide](https://platform.claude.com/docs/en/agent-sdk/sessions); [host integration contract](../../architecture/host-integration.md).

2. **Startup work can move off the request path, but measured speedup is unproven.** TypeScript `startup()` spawns and initializes Claude Code before a prompt; `prewarm()` (alpha in v0.3.282, 2026-09-24) starts a spare before the session/folder is known. A spare uses roughly 230-260 MB; session hooks, MCP servers and project context wait until claim. SDK v0.3.281 (2026-09-23) reports moving MCP handshake into the SDK (up to 250 ms initialization wait), responding to initialize before background startup, and shrinking the SDK bundle from 1.47 MB to 0.97 MB. These vendor release claims are not independent benchmarks; no end-to-end latency percentage is published. **Applicability:** consider `startup()` for a long-lived service; prewarm's alpha status and memory cost matter. **Certainty: high for behavior; vendor-reported for performance.** Sources: [TypeScript SDK reference](https://docs.anthropic.com/en/docs/claude-code/sdk/sdk-typescript#startup); [v0.3.281 release notes](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.281); [v0.3.282 release notes](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.282).

3. **The stream exposes lifecycle and latency signals beyond final text.** Results can carry session IDs, subtype, terminal reason, usage/cost and structured output; stream events can expose partial output, subagent ancestry and task state. TypeScript v0.3.287 (2026-10-01) adds remote-session queue-wait fields and fixes partial-message completion markers. v0.3.206 (2026-07-10) added `command_lifecycle` terminal states; v0.3.203 (2026-07-07) added a full `background_tasks_changed` snapshot. A started event alone is not completion. **Applicability:** correlate events by session/message/task IDs, but keep IssueOps `next` and its durable record as lifecycle authority (`.issueops/AGENT_WORKFLOW.md:85`). **Counterevidence:** SDK schemas evolve and describe host activity, not IssueOps lease/phase truth. **Certainty: high for fields/releases; official Anthropic sources only, no independent corroboration.** Sources: [TypeScript changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md); [v0.3.203](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.203); [v0.3.206](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.206); [v0.3.287](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.287); [Python SDK reference](https://docs.anthropic.com/en/docs/claude-code/sdk/sdk-python).

4. **Structured agent output is built in, but success alone is insufficient.** Set `outputFormat`/`output_format` to `json_schema`; results carry validated `structured_output`. Invalid schemas fail at startup; generation may retry then return `error_max_structured_output_retries`. A `success` result can lack the field, so check subtype and value. TypeScript v0.3.287 also omits ordinary MCP `structuredContent` above 1,048,576 JSON characters and marks it; that field is distinct from agent `structured_output`. **Applicability:** useful for machine-consumed reports if failure and missing output are explicit. **Counterevidence:** schema validity does not prove factual correctness. **Certainty: high; vendor docs/releases, no independent confirmation.** Sources: [Agent SDK structured outputs](https://platform.claude.com/docs/en/agent-sdk/structured-outputs); [v0.3.287 release](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.287).

5. **Repository fit is exploratory, and one local claim is stale.** Project architecture documents Claude via `CLAUDE.md`, shared skills, user-scope MCP and context hooks; they do not prescribe the Agent SDK. A prior note says structured output validation is “Not built-in” (`.issueops/research/multi-agent-orchestration-quality-patterns.md:153`), contradicted by current first-party docs. These sources establish SDK capability, not adoption or benefit in this Go harness. Latest verified versions: Python v0.2.163 (2026-09-30) and TypeScript v0.3.287 (2026-10-01): [Python release](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.163), [TypeScript release](https://github.com/anthropics/claude-agent-sdk-typescript/releases/tag/v0.3.287). **Applicability:** correct the old note if reused; benchmark any proposed bridge against the existing CLI/MCP contract. **Certainty: high for document mismatch; repository search found no direct SDK integration.**

## Source quality and limits

Claims come from Anthropic docs and Anthropic-owned GitHub SDK releases/changelogs; published dates were checked in GitHub Releases API metadata. These are one official source family, not independent corroboration. The local synthesis is cited only as dated counterevidence. No performance percentages are inferred.

Failed retrieval/verification attempts: `read` on the research directory returned `EISDIR`; three `webfetch` calls using unsupported `format: "json"` were rejected by tool validation. Re-fetching the official GitHub API as text succeeded. The first untracked-file `--no-index --check` found trailing whitespace after the retrieval date; it was removed, and the final check reports no whitespace (status 1 only because the files differ). No public official URL remained inaccessible.

## EXPAND

- Benchmark `startup()` against `query()` in a long-lived integration, measuring spawn, initialize, first-token latency, RSS and MCP readiness separately; no reproducible benchmark was found.
- If an SDK integration is proposed, map its result/events to IssueOps telemetry while retaining `issueops next` and durable state as authority; reconcile the stale local claim. This lane alone does not support adoption.
