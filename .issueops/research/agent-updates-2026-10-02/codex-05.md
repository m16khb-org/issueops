# Codex MCP integration and tool discovery

Retrieved: 2026-10-02
Scope: One bounded evidence lane for IssueOps performance, optimization, and visibility. Codex local clients and OpenAI API agent runtimes are treated as distinct products.

## Findings

1. **The Codex local MCP catalog has a measurable startup window and explicit scope controls.** The current official Codex MCP guide says optional servers receive a default 1,000 ms grace period while Codex builds the initial tool catalog; required servers instead use their configured startup timeout. It also documents `enabled_tools`/`disabled_tools`, per-tool output-token limits, and 10-second/60-second default server/tool timeouts. These are concrete knobs for managing initial availability and oversized tool exposure, not evidence of measured speedups. IssueOps currently configures a 30-second `startup_timeout_sec` and does not set `required` (`internal/adapter/codex/install_config.go:57-62`; `configs/codex/mcp.config.toml:1-6`). **Certainty: high** for documented defaults and repository configuration; the live guide has no version stamp. **Applicability:** compare startup and first-tool availability before changing the 30-second server timeout or tool scope. **Counterevidence:** Codex stable 0.160.0, published 2026-10-01 ([release metadata](https://api.github.com/repos/openai/codex/releases/401312540)), does not list an MCP startup/catalog change; this does not establish when the documented behavior entered Codex. [Codex MCP guide](https://learn.chatgpt.com/codex/extend/mcp); [0.160.0 release notes](https://github.com/openai/codex/releases/tag/rust-v0.160.0).

2. **IssueOps advertises an eager, deterministic tool list rather than a project-specific lazy-discovery layer.** Its ordered `catalogSections` is the single source for `tools/list` exposure and dispatch; `AdvertisedTools` includes every section marked advertised, and the order is pinned by the MCP golden snapshot (`internal/adapter/inbound/catalog/mcp/catalog.go:4-18,36-64`). The Codex guide separately documents `/mcp` for viewing connected servers and server `instructions` as cross-tool guidance, with the first 512 characters self-contained. **Certainty: high** for IssueOps catalog behavior and documented client surfaces. **Applicability:** if catalog size or selection cost is suspected, first measure list size/schema tokens and test Codex allow/deny filters against representative tasks; do not assume MCP server tools are automatically deferred by Codex CLI. **Counterevidence:** the OpenAI tool-search guide describes deferred discovery for Responses API and Agents API, but that is not documentation of Codex local MCP behavior. [Codex MCP guide](https://learn.chatgpt.com/codex/extend/mcp); [Tool search guide](https://developers.openai.com/api/docs/guides/tools-tool-search).

3. **Codex documents direct observability for MCP discovery and calls.** Its current official configuration guide names `mcp.tools.list.duration_ms` (with cache state), `mcp.tools.fetch_uncached.duration_ms`, `mcp.call` and `mcp.call.duration_ms`; tool metrics include tool name, success, and duration. The configuration reference exposes an `otel.metrics_exporter` setting, defaulting to `statsig`. **Certainty: high** that these signals and a metrics exporter are documented; availability depends on client version and effective telemetry settings, neither pinned by the live page. **Applicability:** use these metrics to separate catalog/list latency, cache misses, and slow tool execution before optimizing IssueOps handlers. Do not report performance gains until measured. **Counterevidence:** Codex 0.160.0 release notes contain plugin-manifest caching and HTTP connection reuse, but no MCP list/call telemetry change; plugin work is not MCP performance evidence. [Codex configuration guide](https://learn.chatgpt.com/codex/config-advanced/); [configuration reference](https://learn.chatgpt.com/codex/config-file/config-reference); [0.160.0 release notes](https://github.com/openai/codex/releases/tag/rust-v0.160.0).

4. **“Tool search” is documented for API agent runtimes, not as a Codex CLI MCP setting.** The OpenAI guide says Responses API tool search defers definitions until runtime; it describes automatic MCP discovery in the Agents API when the model/provider supports it. The [API changelog](https://developers.openai.com/api/docs/changelog) dates the tool-search release to 2026-03-05 and Agents API public beta to 2026-09-10. Those are actual API releases, not Codex CLI release claims. **Certainty: high** for this product distinction in current first-party docs. **Applicability:** treat API tool search as a future design lead only if IssueOps adds an API-hosted agent surface; for today’s Codex host, focus on local MCP config, stable server catalogs, and Codex telemetry. **Counterevidence:** Codex does expose MCP servers to local clients and offers tool allow/deny settings, so lack of a documented Codex CLI `tool_search` option does not mean MCP tools cannot be selected or filtered.

## Source quality and limitations

OpenAI Codex docs, OpenAI’s API changelog, and the upstream `openai/codex` release page are first-party sources; they are not independent corroboration of one another. IssueOps source is primary evidence for this repository only. No independent external corroboration was found or used. The 2026-10-01 stable Codex release is version 0.160.0 (GitHub release metadata gives `published_at: 2026-10-01T20:19:13Z`); the cited live Codex configuration page and MCP guide provide no corresponding feature release date/version, so their behavior is not attributed to 0.160.0. The earlier MCP-specific official evidence is version-agnostic; newer official Codex release notes do not identify a later MCP tool-discovery release.

Access note: `https://learn.chatgpt.com/codex/telemetry` returned “Page not found” and was not used; MCP telemetry claims above were retrieved from the official Codex configuration reference. Failed commands: none.
