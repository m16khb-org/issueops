# Codex multi-agent roles and concurrency

**Retrieved:** 2026-10-02
**Scope:** One bounded evidence lane for IssueOps performance, optimization, and visibility.
**Release context:** The official Codex CLI release `0.160.0` was published 2026-10-01. The Codex multi-agent and configuration pages are live, unversioned documentation, so their current settings are not asserted to have shipped in that exact release.

## Findings

1. **Codex supports both built-in and narrowly defined custom agent roles.** The current Codex guide lists built-ins `default`, `worker`, and `explorer`; custom roles are standalone TOML files with a name, selection description, and developer instructions. They can also set model, reasoning effort, sandbox mode, and selected session settings. Model selection resolves from explicit spawn values, then `[agents]` defaults, then the parent; custom agent values can override that resolution. **Certainty: high** for the live documented contract, but not version-pinned. **Applicability:** Codex-only roles could specialize read-only exploration or review while leaving shared IssueOps workflow skills as the cross-host source of truth (`.issueops/architecture/host-integration.md:13-17`). **Counterevidence:** role descriptions and prompt configuration do not ensure higher accuracy or speed; duplicating shared skill policy in Codex-specific roles risks drift.

2. **Concurrency is configurable, but the current official docs do not publish a fixed default.** `agents.max_concurrent_threads_per_session` caps simultaneously open spawned-agent threads and excludes the primary thread; unset, Codex chooses the default. `agents.max_threads` is a legacy alias. The feature is documented as stable and enabled by default. **Certainty: high** for setting semantics; **medium** for version applicability because the page is live. **Applicability:** an explicit cap can bound fan-out and resource exposure in a Codex project, but should be selected from measured workload behavior rather than copied from search snippets or another API’s limit. **Counterevidence:** a thread cap is not a throughput guarantee and does not mean every task benefits from parallelism. Source: [Codex configuration reference](https://developers.openai.com/codex/config-reference).

3. **OpenAI recommends parallelism for independent, read-heavy work and warns against assuming write-heavy work scales.** The guide recommends delegating code exploration, tests, triage, and summarization; keeping the parent focused on decisions; and returning summaries rather than noisy logs. It says subagents can save time on independent work, but also consume more tokens than comparable single-agent work; concurrent writes can create conflicts and coordination overhead. **Certainty: high** as the vendor’s explicit guidance, not an independently measured result. **Applicability:** issueops research, evidence gathering, or independent read-only checks are plausible bounded parallel tasks. Serialize shared-state mutation and dependent implementation steps. No latency, token, or cost improvement has been measured for this repository. Source: [Codex multi-agent guide](https://developers.openai.com/codex/subagents).

4. **The latest checked CLI release adds operational visibility and a subagent failure-path improvement, not a performance claim.** Release `0.160.0` (published 2026-10-01) adds history pagination in the agent command center; its notes also say subagents retain environments that are still starting and receive configuration or preparation failures. These support better inspection and failure diagnosis. The same release notes report no quantified multi-agent speedup. **Certainty: high** for the release-note statements; their user impact is not benchmarked. **Applicability:** visibility and failure classification are useful criteria for any future IssueOps/Codex adapter evaluation. **Counterevidence:** release notes do not establish latency, token efficiency, or that IssueOps currently consumes Codex subagent lifecycle events. Source: [Codex 0.160.0 release notes](https://github.com/openai/codex/releases/tag/rust-v0.160.0); published timestamp: [official GitHub release metadata](https://api.github.com/repos/openai/codex/releases/401312540).
