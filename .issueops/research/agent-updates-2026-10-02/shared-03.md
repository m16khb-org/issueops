# MCP tool metadata and resource links: evidence report

**Retrieved:** 2026-10-02
**Scope:** MCP tool annotations, output schemas, resource links, and cache-oriented catalog behavior relevant to shared issueops improvements.

## Findings

1. **Structured outputs are standardized, but issueops currently flattens responses to text.** The MCP `2026-07-28` specification permits optional `outputSchema`; when supplied, servers must return conforming `structuredContent`, and clients should validate it. The `2025-06-18` changelog dates the introduction of structured tool output and resource links. In issueops, `mcpcontract.Tool` contains only `Name`, `Description`, and `InputSchema` (`internal/contract/mcp/catalog_types.go:3-8`); `ToolMaps` exports only those three fields (`internal/adapter/inbound/catalog/mcp/catalog.go:70-79`), and `registerAllTools` constructs `mcp.Tool` without `OutputSchema` or annotations (`cmd/issueops/mcpcli/mcp_sdk_server.go:134-151`). Normal tool outcomes are JSON-marshaled into `TextContent` rather than `structuredContent` (`mcp_sdk_server.go:123-130`). **Certainty: high.** Applicability: typed results could improve machine-readable visibility and validation across hosts, but require shared-contract and golden changes. Counterevidence: output schemas are optional; text output is valid and the SDK supports older peers. The repository pins Go SDK `v1.6.1` (`go.mod:31-34`), predating its `v1.7.0` support for protocol `2026-07-28`; do not treat newer protocol features as available without an upgrade.

2. **Tool annotations are behavioral hints, not enforcement, and are absent from the shared catalog.** The official annotations overview describes `readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint`; the spec requires clients to distrust annotations from untrusted servers. Issueops has no annotation fields in its shared `Tool` contract or catalog projection (anchors above), so it cannot currently communicate these hints through its tools. **Certainty: high for the protocol contract and local omission.** Applicability: truthful hints could help clients expose behavior and drive trusted-server UX, supporting visibility. They must not replace issueops command policy, authorization, or write controls. Counterevidence: annotations cannot guarantee behavior; the official overview says client handling and adoption vary, so adding hints alone does not improve safety or prove a runtime effect.

3. **Resource links can expose large or reusable results without embedding them, but current tool-result conversion drops non-text blocks.** A `resource_link` in a tool result gives a URI the client may fetch or subscribe to; the `2025-06-18` changelog confirms this became a protocol feature. Issueops already advertises reusable resources such as `issueops://docs`, `issueops://project-docs`, and `issueops://state` (`internal/contract/mcp/resource_catalog.go:3-14`), and its architecture assigns context to resources and actions to tools (`.issueops/architecture/runtime.md:175-181`). However, the direct-result converter keeps only items whose type is `text` (`cmd/issueops/mcpcli/mcp_sdk_server.go:98-121`), so it does not preserve a `resource_link` as a native SDK content item. **Certainty: high.** Applicability: returning links for substantial reports or indexes could reduce repeated payloads and improve discoverability. Counterevidence: linked resources are optional and are not guaranteed to appear in `resources/list`; current dedicated resource URIs already provide a separate context surface.

4. **Catalog determinism and cache hints offer a measurable performance lead, not a promised saving.** The `2026-07-28` changelog says deterministic tool order supports client caching and prompt-cache hit rates; the MCP release post (2026-07-28) adds `ttlMs` and `cacheScope` hints to list/read results. The Go SDK `v1.8.0` release (published 2026-09-14) adds `ServerOptions.SetCacheable`; it explicitly adds no protocol revision beyond `2026-07-28`. Issueops already pins advertised order with a golden (`internal/adapter/inbound/catalog/mcp/catalog.go:36-45`) and one observed `tools/list` contained 51 tools / 30,888 bytes (`.issueops/research/agent-updates-2026-10-02/mcp-baseline.md:22-27`). That byte count is not token count or proof the host injects the whole list each turn. **Certainty: high for source statements and the recorded single run; low for any end-to-end performance effect.** Applicability: first measure host-side tool loading, cache behavior, and repeated context before considering grouping or deferral. Counterevidence: SDK upgrades and client adoption vary; `go.mod` remains at `v1.6.1`, and one warm, uncontrolled response-time observation cannot establish a regression or improvement.

Protocol semantics above are official single-source claims; the specification, changelog, and project blog share MCP maintainership and are not independent corroboration. The official Go SDK release is a separate implementation record that corroborates version support and cache-control availability, but is not independent governance or a third-party interoperability test. No independent external corroboration was used.

## EXPAND

- Measure actual Codex/Claude/Omo tool catalog injection, repeated-list caching, and selection latency before estimating benefit; existing local evidence is only one server response.
- Prototype-preserving round-trip tests for `outputSchema`/`structuredContent` and `resource_link` against the pinned and upgraded Go SDK; confirm SDK and host support before changing the shared contract.
- Inventory tools by read/write/destructive/idempotent behavior before assigning annotations; compare every hint with core policy rather than treating metadata as policy.
