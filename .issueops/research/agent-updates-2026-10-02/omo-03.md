## Findings

1. **Overrides have two distinct precedence systems.** The [configuration reference](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/docs/reference/omo-json.md) specifies user config, then ancestor project configs, nearest last; objects deep-merge, arrays replace. The resolved harness view then folds shared keys, `[native]`, active `profiles.<name>`, and that profile's `[native]`. Separately, `model_profile` controls the main session, not category children; it is not the config-overlay `profiles` key. **Certainty:** high for the documented contract, supported by fetched loader source. **Applicability:** IssueOps should diagnose the resolved layer and harness before suggesting a model change. **Counterevidence:** the reference explicitly says interactive TUI sessions do not apply `model_profile`; desktop/headless behavior must not be generalized to every surface.

2. **A category/model combination is rejected, including inherited batch overrides.** [Validation source](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/packages/senpi-task/src/tools/task/validation.ts), lines 101-109 and 175-187, enforces category XOR agent and rejects a nonempty `model` on category routing. Batch validation computes `input.model ?? params.model` before checking the effective target. Installed `/Users/habin/node_modules/omo-ai/plugin/extensions/omo-task.js:2`, function `fK`, contains the same `category_with_model` branch and explanatory error. **Certainty:** high, source plus installed artifact agreement. **Applicability:** IssueOps delegation templates should choose category configuration or explicit named-agent routing, never both. **Counterevidence:** named-agent spawns can accept explicit models; this is not a universal override prohibition.

3. **Nonempty `models[]` overrides `model`, but pins do not guarantee builtin rescue.** [Category resolver](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/packages/senpi-task/src/category/resolver.ts), lines 126-145 and 382-406, makes the first canonical entry primary and the rest user fallbacks. [Delegate selection](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/packages/delegate-core/src/model-selection.ts), lines 92-130, promotes an available user fallback when the primary is missing, otherwise returns the user selection before reaching builtin resolution. The category resolver subsequently requires a concrete registry match. Installed bundle functions `Hg`, `Yg`, and `tg` reproduce these branches. **Certainty:** high for selection behavior. **Applicability:** use explicit provider-qualified chains when reliability matters; expose unavailable pins instead of assuming recovery. **Counterevidence:** the [matching guide](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/docs/guide/agent-model-matching.md) says configured chains are tried before builtins. Runtime retries are separate: builtin remaining rungs extend a chain only when the selected model can be located in it; arbitrary pins leave user chains untouched.

4. **Shipped defaults encode effort and provider choices, not measured speedups.** The release notes move `deep-high` to GPT-6 Astra **high**, while `deep-low` stays GPT-6.1 Sol **medium**. [Fallback source](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/packages/senpi-task/src/category/fallback-chains.ts), lines 56-77 and 94-95, confirms these and `quick` on GPT-6 Luna Fast **low**. GPT rungs prioritize ChatGPT subscription over `openai`; `deep-high` has one model rung across four providers. **Certainty:** high for routing constants, not comparative model quality. **Applicability:** bounded exploration and implementation can use different effort budgets. **Counterevidence:** registry availability and overrides change actual selection; no latency, cost, or quality benchmark was run.

5. **Existing resolution metadata can support visibility without copying routing into IssueOps.** Resolver lines 274-281, 346-353, and 482-489 provide attempted chains, missing providers, gateway-only alternatives, selected model, and fallback-match status. [Runtime chain source](https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/v5.1.8/packages/senpi-task/src/model-chain.ts), lines 19-42, records `requested_model` and available later `fallback_models`. **Certainty:** high for internal fields; medium for a future integration. **Applicability:** distinguish requested, selected, and retry models in evidence. **Counterevidence:** these internal values do not establish a stable IssueOps-accessible API or prove that a retry actually occurred.
