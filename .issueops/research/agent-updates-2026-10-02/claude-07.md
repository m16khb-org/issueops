# Claude Code OpenTelemetry cost and usage

**Retrieved:** 2026-10-02
**Scope:** Public Anthropic/Claude Code sources and this repository; a bounded evidence lane for IssueOps performance, optimization, and visibility.
**Source independence:** Claude-specific product behavior below is supported by Anthropic documentation and release notes, all one publisher; this is official single-source evidence, not independent corroboration. One user-authored GitHub issue is cited as an unverified field report, not confirmation. No independent performance benchmark was found.

## Findings

1. **Claude Code exposes useful signals for separating model cost from execution time.** Its Monitoring reference lists `claude_code.cost.usage` (USD), `claude_code.token.usage` (tokens), `claude_code.active_time.total` (seconds), session, tool-decision, commit, and PR counters. Cost and token counters increment after each API request; token types include input, output, cache-read, and cache-creation. Optional beta traces add request duration, time-to-first-token, retries/attempts, tool execution and permission-wait durations, plus agent/subagent identifiers. This can support a controlled IssueOps workload comparison without treating tokens as elapsed time. **Certainty: high** for documented schema; **applicability: high** to a later opt-in benchmark, not evidence of IssueOps speedup. **Counterevidence:** traces are off by default and beta; several signals are absent unless the corresponding feature is enabled. The docs do not supply an IssueOps baseline or performance result. Sources: [Monitoring, metrics and trace schema](https://code.claude.com/docs/en/monitoring-usage#available-metrics), retrieved 2026-10-02; [official v2.1.287 release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.287), dated 2026-10-01.

2. **The USD counter is an estimate, not a billing authority, and plan usage is a different measure.** Anthropic says Claude Code computes cost from token counts at list prices unless managed `modelPricing` overrides are applied; configured rates change the reported estimate, not the charge. The `/usage` session cost is not relevant to billing for Pro/Max subscriptions, where plan-usage bars are shown. OTel is the documented near-real-time path for per-user token and cost metrics across providers, but no telemetry metric for plan-limit utilization is listed. **Certainty: high** for the distinction as documented, with no independent corroboration. **Applicability: high** when comparing IssueOps workloads: label estimates and subscription usage separately, and do not infer invoice spend from the metric. **Counterevidence:** an open-source user feature request for exporting usage-limit utilization was closed `not_planned` on 2026-02-22; this is issue status, not an Anthropic technical explanation. Sources: [Manage costs effectively](https://code.claude.com/docs/en/costs#track-your-costs) (live docs; no publication date stated), [Monitoring](https://code.claude.com/docs/en/monitoring-usage), and [issue #16942](https://github.com/anthropics/claude-code/issues/16942) (created 2026-01-08; retrieved 2026-10-02).

3. **Attribution and content detail have explicit cost/cardinality and privacy tradeoffs.** By default, cost/token metric labels redact some agent, skill, plugin, and MCP names; `OTEL_LOG_TOOL_DETAILS=1` reveals real names. Anthropic says high-cardinality resource attributes increase backend storage costs and lower cardinality generally improves performance/storage cost at the cost of less granular analysis. Prompt, tool-detail, and tool-content logging are separately gated; raw API-body logging can include the entire conversation. Release `v2.1.287` (2026-10-01) added duplicate `prompt_text` to `user_prompt`, explicitly instructing collectors to drop or mask it wherever they handle `prompt`. **Certainty: high; official single-source claim. Applicability: high** to designing low-cardinality, content-minimizing measurements. **Counterevidence:** removing session or repository attributes can make per-session or per-repo analysis impossible; the right balance depends on the question and backend. Sources: [Monitoring, configuration and cardinality controls](https://code.claude.com/docs/en/monitoring-usage#common-configuration-variables), retrieved 2026-10-02; [v2.1.287 release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.287), 2026-10-01.

4. **Treat attribution fields as version-sensitive, not guaranteed ground truth.** A user-authored issue reports `query_source` disappearing from API events and cost/token counters starting 2026-05-13 in both Claude Code and Cowork, with dashboard impact on main/subagent/auxiliary attribution. The issue was closed `not_planned` on 2026-08-02, with no resolution documented in the fetched issue. That is anecdotal external counterevidence to assuming the documented field is always populated; it is not independent reproduction or proof the bug persists today. Anthropic's current docs still define the field. **Certainty: high** that the issue contains this report and status; **low** that it describes current behavior. **Applicability: medium-high:** any future attribution dashboard should retain app version and validate field completeness on real exports. Sources: [issue #59942](https://github.com/anthropics/claude-code/issues/59942) (opened 2026-05-17, retrieved 2026-10-02); [Monitoring, cost counter](https://code.claude.com/docs/en/monitoring-usage#cost-counter).

5. **Do not place this instrumentation in IssueOps’ default Claude hook.** The repository explicitly keeps `SessionStart` context-only and excludes telemetry, runtime diagnostics, and state writes (`.issueops/AGENT_WORKFLOW.md:68`). Its constitution says optimization must be justified by measured bottlenecks (`.issueops/CONSTITUTION.md:48,55`). This makes native OTel a plausible external/opt-in measurement source, but does not authorize expanding lifecycle hooks or establish that IssueOps needs a new telemetry subsystem. **Certainty: high** for repository rules; **applicability: high.** No local OTel configuration or running Claude export was inspected.
