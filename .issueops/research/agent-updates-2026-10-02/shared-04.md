# OpenTelemetry GenAI agent semantic-convention stability

**Retrieved:** 2026-10-02
**Scope:** One evidence lane for IssueOps performance, optimization, and visibility. Public official OpenTelemetry sources and repository guidance were checked; no implementation or telemetry configuration was changed.

## Findings

1. **Agent conventions remain Development, not a stable contract.** The official agent-span specification labels the whole document and the individual operations (including `create_agent`, `invoke_agent`, `invoke_workflow`, `plan`, and `execute_tool`) Development. It uses `SHOULD`/`MAY` guidance for operation naming and span shape, but its status means consumers should not assume long-term compatibility. The official GenAI repository release page says “There aren’t any releases here”; its changelog contains only “Unreleased,” with no versioned package or dated release to cite as a stability milestone. **Certainty: high for the retrieved pages, not a claim about unobserved private/vendor implementations.** Sources: [agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md); [release page](https://github.com/open-telemetry/semantic-conventions-genai/releases); [changelog](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/CHANGELOG.md).

2. **The schema is useful as an observational vocabulary, but should be versioned behind an IssueOps-owned adapter.** The current draft supplies distinct operations for agent creation/invocation, workflow invocation, planning, and tool execution. `invoke_agent` recommends a `CLIENT` span and `gen_ai.operation.name=invoke_agent`; agent name, provider, and request model are called out as useful at span creation for sampling. For IssueOps this could make delegated work, tool execution, and model-call boundaries easier to correlate, and support latency/error attribution without asserting an optimization benefit. Keep stable internal event/metric names and translate to GenAI attributes at export or query boundaries; pin any mapping to a reviewed upstream revision and allow it to evolve. This matches the repo’s requirement that optimization follow measured bottlenecks and avoid unneeded cache/state (`.issueops/CONSTITUTION.md:43-59`). **Certainty: high on the convention text; medium on IssueOps fit until its actual telemetry surface and instrumentation points are mapped.** Source: [agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md).

3. **The stability rules explain why Development is consequential.** OpenTelemetry’s official semantic-convention groups document says group stability is required, defaults to Development, and cannot regress after reaching Stable; unstable groups may change references and requirements. It also says stable groups may include unstable attributes only as opt-in. This makes the agent draft’s Development status a concrete compatibility risk for dashboards, queries, and consumers, rather than a merely editorial badge. The separate specification is generic policy, not independent confirmation that this particular GenAI draft is stable; the draft itself says the opposite. **Certainty: high.** Sources: [semantic-convention groups](https://opentelemetry.io/docs/specs/semconv/general/semantic-convention-groups/); [agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md).

4. **Observability detail has privacy and cost tradeoffs.** The broader GenAI span conventions explicitly flag input/output messages, system instructions, prompt variables, and tool definitions as potentially sensitive; message and instruction fields are opt-in, and tool definitions can be large. For IssueOps, use operation, duration, outcome, and low-cardinality identifiers first; do not capture prompts, tool payloads, or model outputs by default. The official draft provides no IssueOps-specific cost or performance measurements, so no overhead or speedup percentage is supportable. **Certainty: high on official warnings; medium on the proposed default for this repository.** Source: [GenAI client spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md#capturing-instructions-inputs-and-outputs).

## Source assessment

The specification pages, repository release page, and changelog are primary sources maintained by OpenTelemetry, not independent corroborations of one another. OpenTelemetry’s May 2026 article independently in publication context calls GenAI conventions “emerging” and agentic workflow observability a continuing need; this supports, but does not itself establish, the agent-page maturity label ([official article](https://opentelemetry.io/blog/2026/otel-grad-now-what/)). No independent third-party claim is used as confirmation.
