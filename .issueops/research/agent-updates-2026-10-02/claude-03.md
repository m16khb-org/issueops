# Claude MCP tool search and deferred loading

**Retrieved:** 2026-10-02
**Scope:** Public Anthropic documentation and release notes, cross-checked against this repository.
**Evidence standard:** Official-source claims below are directly fetched. The cited product sources are all published by Anthropic; docs and blog articles from the same vendor are corroborating descriptions, not independent confirmation. No independent performance replication is relied upon here. All cited pages were accessible; there were no failed commands.

## Findings

1. **Claude Code has a host-level MCP tool-search path, enabled by default, but it is conditional.** Its MCP guide says tool search handles waits for still-connecting servers and lets Claude discover newly connected server tools later in the same turn. It also documents configurations without search: `ENABLE_TOOL_SEARCH=false`, a custom `ANTHROPIC_BASE_URL`, and some older Google Cloud model deployments. Microsoft Foundry can fall back to upfront loading after server-side rejection. Thus “default” is not “always available.” **Certainty: high** for documented behavior; **applicability: high** to diagnosing Claude-specific visibility/startup behavior. **Counterevidence/limits:** the guide describes host implementation, not an IssueOps-controlled switch or a guarantee of lower wall-clock latency. [Claude Code MCP guide, “Tool availability” and linked “Scale with MCP tool search”](https://code.claude.com/docs/en/mcp#tool-availability), retrieved 2026-10-02.

2. **API deferred loading saves model-context space, not the client’s tool catalog/request payload.** The API requires the full definitions of deferred tools in every request, but excludes those definitions from the initial context; search returns references that the API expands when selected. It supports regex or BM25 search, up to 10,000 deferred tools, and recommends keeping 3–5 common tools immediately available. The same reference says search is most relevant from 10 tools or >10k definition tokens and is less useful below 10 tools or when all tools are common. **Certainty: high** (API contract); **applicability: conditional** on measured prompt/tool-definition cost. **Counterevidence:** the documented token/context reduction does not mean fewer bytes sent by an API client or lower end-to-end latency; search adds a retrieval step. The `20251119` tool identifiers and `advanced-tool-use-2025-11-20` beta header are version markers in the official docs, not a claim that every Claude Code host uses that exact API surface. [Tool search API reference, “Deferred tool loading,” “When to use,” and “Usage”](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool), retrieved 2026-10-02.

3. **Deferred tools can preserve prompt-cache prefixes when the tool set would otherwise change.** Anthropic’s Claude Code engineering article explains that tool definitions are in the cached prefix and changing the set can cause cache misses; it describes stable lightweight deferred stubs, with full definitions added on discovery. The API reference independently describes deferred definitions as excluded from the prefix and discovered references added inline. **Certainty: high** that this is Anthropic’s documented mechanism; **applicability: useful design principle** for cache stability, not measured IssueOps savings. **Counterevidence:** both sources are Anthropic publications, so this is same-vendor corroboration, not independent validation; neither measures this repository’s cache-hit rate. The fetched blog body has no publication date; the latest official Claude Code changelog fetched here is v2.1.287, dated 2026-10-01. [Anthropic engineering article](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything), [API reference](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool#deferred-tool-loading), and [advanced-tool-use announcement](https://www.anthropic.com/engineering/advanced-tool-use), retrieved 2026-10-02.

4. **Do not conflate Claude Code’s MCP discovery cache with deferred tool loading or result handling.** Claude Code documents a cached remote HTTP/SSE server tool list that can avoid reconnecting at startup and connects on first tool use. The cached status requires v2.1.221 or later; the cache is off by default except gradual rollout, and before v2.1.238 it was on by default. In v2.1.287 (2026-10-01), Claude Code changed MCP server `alwaysLoad: false` to defer all of that server’s tools behind tool search. The same release separately improved handling of large MCP tool results: less memory use, smaller session files, and no extra upload solely to count tokens for results far over the limit. The result-handling change is not itself deferred tool loading. **Certainty: high** (versioned official docs/changelog); **applicability: high** when diagnosing Claude MCP startup, context, or large-result costs. **Counterevidence:** the changelog gives no performance measurements; cache state and server transport affect startup, and none of these changes guarantees the model will select the right tool. [MCP guide, “Server status detail”](https://code.claude.com/docs/en/mcp#server-status-detail); [Claude Code changelog v2.1.287](https://code.claude.com/docs/en/changelog), retrieved 2026-10-02.

5. **The IssueOpsBasicTools subcatalog alone does not establish the size of IssueOps's advertised MCP catalog.** It returns only `issueops_execution` (`internal/contract/mcp/issueops_catalog.go:3-8`), and its regression test asserts that this subcatalog contains exactly that one tool (`internal/adapter/inbound/catalog/mcp/issueops_catalog_test.go:9-14`). The full advertised catalog is assembled from multiple domain subcatalogs in `internal/adapter/inbound/catalog/mcp/catalog.go:18-44`; its total tool count and rendered schema size have not been measured in this research. The repository’s MCP design guidance calls for task-specific descriptions and deterministic ordering (`.issueops/architecture/runtime.md:175-181`). **Certainty: high** for the cited subcatalog and composition facts; **applicability: defer any adoption judgment** until the full advertised catalog's tool count, token cost, Claude visibility, and latency are measured. **Counterevidence:** one domain subcatalog can still have a large schema; neither that fact nor its tool count settles the aggregate.
