# Claude Code plugin skills: distribution, compatibility, and visibility

**Retrieved:** 2026-10-02

**Scope:** Public official Claude sources and this repository only.
**Question:** What do Claude Code's current plugin/skill distribution and compatibility rules imply for IssueOps optimization and visibility?

## Method and evidence quality

Fetched the official Claude Code plugin, skill, marketplace, loading, install, cost-measurement, changelog, and v2.1.287 release pages, plus the independent Agent Skills specification. Read the local upstream catalog, adapter implementation, and operations guide. Claude's docs pages and its GitHub release notes are all first-party Anthropic sources; multiple pages from that publisher are not independent corroboration. Agent Skills is an independent standard and corroborates the portable `SKILL.md` structure only, not Claude runtime behavior. Repository code corroborates IssueOps behavior only. No independent public source was found that verifies Claude's runtime-specific plugin claims.

## Findings

1. **Standalone skills and plugins are different distribution units, but share skill content.** Claude's official skill docs say skills use `SKILL.md` and conform to the Agent Skills open standard, while Claude-specific frontmatter features extend it. The independent specification confirms the minimum directory/`SKILL.md` shape and recommends progressive disclosure: metadata at startup, the body on activation, referenced resources on demand. Claude's plugin docs describe a plugin as a directory of components installed and updated as a unit; its skills are namespaced as `/<plugin>:<skill>`, unlike ordinary `/skill` names. Sources: [Claude skills](https://code.claude.com/docs/en/skills), retrieved 2026-10-02; [Claude plugins](https://code.claude.com/docs/en/plugins), retrieved 2026-10-02; [Agent Skills specification](https://agentskills.io/specification), retrieved 2026-10-02. **Certainty:** High for documented behavior; the independent source confirms only the shared format. **Applicability:** IssueOps can keep its host-neutral `skills/` links while using plugin installs where namespacing, bundled components, and marketplace version updates matter. **Counterevidence:** Shared `SKILL.md` format does not make Claude-only frontmatter or plugin-specific features portable.

2. **Plugin metadata is a measurable recurring context cost; skill bodies are not always-on.** Claude's official cost guide states that names and descriptions of skills, agents, and commands from enabled plugins enter context every session, whether used or not; component bodies load when invoked. `claude plugin details <name>` reports projected always-on and per-component invocation estimates; `/context` exposes MCP tool context. The guide recommends shortening descriptions or splitting a plugin, and says official-marketplace listings can show context cost before install. Sources: [Measure plugin cost and usage](https://code.claude.com/docs/en/plugins/measure), retrieved 2026-10-02; [Plugin overview](https://code.claude.com/docs/en/plugins), retrieved 2026-10-02. **Certainty:** High, single-source official documentation, not independently benchmarked here. **Applicability:** Treat plugin count/metadata as a performance budget and record actual `plugin details` output before considering changes. IssueOps currently lists four upstream plugins in `configs/upstream.json:3-24`. **Counterevidence:** The documentation gives estimates and no universal performance percentage; the full skill body is not charged every turn, and MCP server context is accounted separately.

3. **The latest observed release has concrete plugin compatibility changes.** Claude Code **v2.1.287**, dated **2026-10-01** in Anthropic's changelog, added Claude Mods (plugins can modify deeper behavior). Its release notes also fix plugin marketplace sparse/git-subdir installs over plain HTTP, SessionStart hooks from synced plugins in new cloud sessions, and skills/plugins failing to load for repositories added mid-session. Sources: [Official v2.1.287 release](https://github.com/anthropics/claude-code/releases/tag/v2.1.287), retrieved 2026-10-02; [Claude Code changelog](https://code.claude.com/docs/en/changelog), retrieved 2026-10-02. **Certainty:** High for shipped release notes; both URLs are first-party and not independent corroboration. **Applicability:** These changes show compatibility depends on install source and session surface, not just `SKILL.md`; validate plugin activation and hooks on the target Claude version/surface. **Counterevidence:** The notes do not establish a regression in IssueOps's current user-scope CLI installation path or quantify performance impact.

4. **IssueOps uses separate plugin and Git-skill paths, and its catalog-count documentation is stale.** The repository declares four plugins and two standalone Git skills (`configs/upstream.json:3-38`). The plugin adapter invokes `claude plugin install ... --scope user` (`internal/adapter/outbound/upstream/claude_plugins.go:53-55`); the skill adapter shallow/sparse-fetches a declared directory and links it under the Claude skill directory (`internal/adapter/outbound/upstream/git_skills.go:14-16,43-67,83-105`). The operations guide says the catalog has “four plugins and one skill” (`.issueops/operations/hosts.md:89-94`), contradicting the current config. **Certainty:** High; these are direct source/config observations. **Applicability:** Fixing the count would improve operator visibility; keep plugin and standalone-skill provisioning, provenance, and update behavior distinct. **Counterevidence:** This inventory mismatch alone does not prove an install defect; existing upstream entries are intentionally optional and do not determine core install success.
