# Agent Client Protocol: current standard and client ecosystem

**Retrieved:** 2026-10-02

**Scope:** One bounded evidence lane for IssueOps performance, optimization, and visibility. Public official ACP/client sources and this repository only; no installs or external mutations.

## Findings

1. **The newest ACP project release is not a new stable wire-protocol version.** The official changelog lists `1.10.2` dated 2026-10-01 as the latest release. It fixes Rust-side skipped-entry deserialization logging, specifically avoiding Serde errors or private payload values in logs. The same changelog tags v2 work as `unstable-v2`; its numbering should not be mistaken for a stable protocol wire version. **Certainty: high** for release/date and stated change (one official source). **Applicability:** This is a concrete privacy/diagnostic trade-off relevant to IssueOps visibility: diagnostics should preserve useful state without exposing malformed payload contents. It supports reviewing redaction and error reporting, not claiming faster execution. **Counterevidence:** The release gives no benchmark or IssueOps-specific evidence; it is a Rust SDK/schema changelog entry, not a Go harness performance report. Source: [official ACP changelog](https://raw.githubusercontent.com/agentclientprotocol/agent-client-protocol/main/CHANGELOG.md), `1.10.2`.

2. **ACP v2 is a draft with session-lifecycle and richer observation semantics.** The first v2 draft was published 2026-07-20. It allows `session/update` outside prompt turns, reports inserted message IDs, describes idle/readiness, and supports stable-ID patches and streamed tool-call content. It also replaces the old text diff with structured file changes. The draft explicitly says details can change, recommends negotiation plus feature flags, and says to retain v1 support. **Certainty: high** for the draft’s own status and design (official announcement and migration guide; both same publisher, not independent). **Applicability:** A future experiment could map structured, incremental progress and file changes to IssueOps run visibility, then measure update volume, display latency, and completeness against current traces. Streaming avoids resending whole tool-call content by design, but no performance percentage or observed speedup is reported. **Counterevidence:** This is not a stable implementation contract; the official guidance is explicitly not to ship v2 by default before stabilization. Sources: [ACP v2 draft announcement](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/announcements/acp-v2-draft.mdx), published 2026-07-20; [v2 migration guide](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v2/migration.mdx).

3. **Registry-backed clients have crossed beyond Zed into JetBrains, but rollout evidence is bounded.** Zed and JetBrains announced a shared ACP Agent Registry; Zed says both clients have built-in registry support and that the registry is the intended distribution layer. JetBrains specifies IDE 2025.3.2+ with AI plugin `253.30387.147` in its announcement; its current help page documents registry installation, manual `acp.json`, and ACP log collection. **Certainty: high** for each vendor’s stated support/version. Zed and JetBrains are separate first-party sources, but describe a coordinated partnership, so this is not independent corroboration. **Applicability:** If IssueOps later evaluates an ACP-facing surface, registry discoverability and bounded logs are concrete client expectations to test. For now, the repository’s external core/thin-adapter direction (`.issueops/architecture/hexagonal-core.md:7-16`) argues against adding a host-specific implementation without a demonstrated use case. **Counterevidence:** Vendor announcements establish availability, not active adoption, compatibility across all agents, or measured performance; JetBrains documents a current WSL limitation. Sources: [Zed registry announcement](https://zed.dev/blog/acp-registry); [JetBrains registry announcement](https://blog.jetbrains.com/ai/2026/01/acp-agent-registry/); [JetBrains ACP help](https://www.jetbrains.com/help/ai-assistant/acp.html).

4. **The official ACP client catalog spans editors, terminal, desktop, mobile, and messaging.** It lists native/editor clients such as Zed and JetBrains plus integrations for Neovim (CodeCompanion, agentic.nvim, avante.nvim, hermes.nvim), Emacs (`agent-shell`), VS Code, Qt Creator, and multiple CLI/TUI and desktop clients. **Certainty: high** that these entries appear in the official catalog on retrieval date; **medium** that each remains actively maintained or fully compatible, because the catalog is not a conformance report. **Applicability:** This breadth suggests client-specific visibility and workflow needs; it is a lead for selecting a representative client only if IssueOps has a concrete interop requirement. **Counterevidence:** Catalog inclusion does not establish usage, maintenance status, feature parity, or performance. The official ACP catalog is first-party ecosystem documentation, not independent corroboration. Source: [ACP clients catalog](https://agentclientprotocol.com/overview/clients).

## Source independence and local fit

Release notes, the v2 draft, and the client catalog are official ACP sources. Zed and JetBrains publish separate product documentation but coordinated the registry launch; do not count them as independent confirmation of outcomes. Local architecture prescribes an external Go core with thin host adapters (`.issueops/architecture/hexagonal-core.md:7-16`). The evidence supports monitoring ACP’s evolving semantics and treating streamed updates as an experiment candidate; it does **not** establish that ACP integration would optimize IssueOps or improve its performance.

## EXPAND
