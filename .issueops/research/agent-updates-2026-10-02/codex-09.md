# Codex telemetry: token usage, cost, and tracing

**Retrieved:** 2026-10-02
**Scope:** Public Codex/OpenAI evidence and IssueOps repository evidence for one bounded performance, optimization, and visibility lane. No performance or cost reduction is inferred.

## Findings

1. **Codex has token counts on request and turn traces, but no dollar-cost trace field is documented.** OpenAI’s merged Codex PR adds completed-response span attributes for input, cached input, output, reasoning output, and total tokens, plus aggregate `codex.turn.token_usage.*` fields on regular user-turn spans. The PR was opened 2026-04-24 and merged 2026-04-28; it does not identify the first released CLI version. Current Codex configuration docs also describe token counts on `response.completed` events. **Certainty: high** that the upstream implementation was merged and these fields are documented; **not established** which release first shipped it. **Applicability:** per-turn traces can correlate token volume with slow turns without joining separate usage records. **Counterevidence:** documentation and PR describe token counts, not a billed-cost attribute or every possible task/agent turn. [PR #19432 and patch](https://github.com/openai/codex/pull/19432) · [Codex advanced configuration: OTel](https://learn.chatgpt.com/codex/config-advanced#otel).

2. **The documented metrics can distinguish usage composition from latency, subject to exporter and client-path support.** The live guide lists `turn.token_usage` as a histogram split by `token_type` (`total`, `input`, `cached_input`, `output`, `reasoning_output`), alongside end-to-end turn and time-to-first-token histograms. It documents OTel as opt-in, with prompt text redacted unless explicitly enabled; metrics collection is separate from OTel log/trace export. **Certainty: high** for the current documentation, which has no version stamp. **Applicability:** capture these dimensions with Codex version and model to identify whether slow IssueOps runs coincide with input growth, reasoning output, or transport latency before changing prompts or workflow. **Counterevidence:** a user report in the official `openai/codex` issue tracker says `codex exec` on 0.144.3 emitted token counts only as trace/log attributes and no OTel metrics. This is a report, not an OpenAI confirmation, and does not verify behavior in current 0.160.0. [Codex advanced configuration](https://learn.chatgpt.com/codex/config-advanced#otel) · [Issue #33668](https://github.com/openai/codex/issues/33668) · [Codex 0.160.0 release](https://github.com/openai/codex/releases/tag/rust-v0.160.0), published 2026-10-01.

3. **Token telemetry supports usage analysis, not direct billing reconciliation.** The OTel fields expose counts and a model label; the guide does not emit dollars or define an account-billing formula. OpenAI’s API pricing page lists rates per million tokens, with separate input, cached-input, and output prices and context-length tiers. Those are API rates, not evidence of the marginal price of a Codex session using ChatGPT-plan authentication or another provider. Even for API usage, an estimate needs the effective model, billing route, applicable rate tier, and correctly separated token categories; a total-token count alone is insufficient. **Certainty: high** about the distinction between the documented telemetry and published API rate card. **Applicability:** if API-backed runs need cost estimates, calculate a separately labeled estimate from metered category counts and a dated rate-card snapshot; compare it with the provider’s billed usage. **Counterevidence:** the API rate card does enable estimates for eligible API usage; it should not be mistaken for an actual Codex bill. [OpenAI API pricing](https://developers.openai.com/api/docs/pricing) · [Codex telemetry configuration](https://learn.chatgpt.com/codex/config-file/config-reference).

4. **IssueOps has a narrow, measurable host baseline, but the checked-in Codex template does not enable OTel.** The tracked template configures only the IssueOps MCP server and a 30-second startup timeout (`configs/codex/mcp.config.toml:1-6`); this proves the template contents, not the effective user-level Codex configuration. Existing research records Codex’s documented MCP-list, cache-miss, and tool-call duration metrics (`.issueops/research/agent-updates-2026-10-02/codex-05.md:12`). IssueOps policy says to optimize only confirmed bottlenecks (`.issueops/CONSTITUTION.md:48-55`). **Certainty: high** for these repository facts. **Applicability:** start with a fixed, representative run cohort; record version, model, auth mode, token categories, turn latency, MCP list/call latency, outcome, and quality. Verify `codex exec` metric availability on the pinned release before relying on histogram dashboards; keep prompts redacted. **Counterevidence:** a missing OTel block in this template does not show whether a user’s global Codex config already enables telemetry.

## Source quality, dating, and limitations

OpenAI’s Codex docs, API pricing page, `openai/codex` PR/release, and repository code are primary sources for their respective claims; the OpenAI pages and repository are not independent corroboration. Issue #33668 is a community-authored reproduction hosted by the upstream project, not vendor-authored confirmation. No independent external reproduction was located. The most recent stable release found is Codex CLI **0.160.0 (2026-10-01)** ([official release metadata](https://api.github.com/repos/openai/codex/releases/401312540)). The OTel guide is undated and version-agnostic; PR #19432 merged **2026-04-28**, outside the preferred 90-day window, so the official documentation search was widened. Release notes for 0.160.0 do not name a telemetry change and do not establish when the PR’s fields first shipped.

**Access / failed retrieval:** `https://learn.chatgpt.com/codex/observability` returned a page-not-found response and was not used. One `webfetch` request for the GitHub release API specified unsupported `format=json`; that attempt was rejected, then the release page was fetched as Markdown and its API metadata endpoint as text. A shell validation using `test $? -eq 1` failed with `test: $?: bad number`; direct content validation replaced it, and no other shell command failed.

- If API-backed cost attribution is needed, reconcile sampled token-category estimates against provider billing for the same model, auth route, and period; otherwise defer dollar-cost tracking because the checked-in Codex template has no telemetry setup and the API rate card is not a Codex subscription bill.
