# 공용 HTTP 경계와 검증 증거에서 놓치기 쉬운 세 가지

- Date: 2026-10-03
- Kind: `caution`
- Source: agent improvements final review F2, F4, race flake
- Summary: 기존 파일 reader를 HTTP 뒤에 노출할 때의 경로 이탈, 문자열만 보는 host receipt 판정, 고정 시간 제한 테스트 세션이 최종 검토와 race 실행에서 드러났다.
- Context: api_doc_review는 prompt_file/diff_file을 ../나 절대 경로로 받아 workspace 밖을 읽었다(F2). host receipt artifact 판정이 docs_index 문자열 존재만 봐서 실패한 호출도 verified가 됐다(F4). startHistoryMCPTestSession의 고정 10초 server context가 전체 -race 부하에서 tools/call EOF를 냈다.
- Resolution: capability 요청의 파일 인자는 symlink 해석 뒤 검증된 scope 안인지 확인하고 밖이면 읽지 않는다. receipt는 host별 artifact를 호출과 응답으로 짝지어 성공 응답(is_error/isError/ok 확인)과 응답 필드의 협상 revision만 증거로 인정하고, 모르는 형식은 unknown으로 둔다. 테스트 MCP 세션 수명은 고정 deadline 대신 t.Context()에 묶는다. 시간이 검사 대상인 기존 wall-clock 테스트(TestCheckLargeBodyIsFast)는 전체 race 부하에서 넘칠 수 있으니 단독 race로 재확인한다.
