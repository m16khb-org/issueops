# #560 Orca 연동 제거 계획

- lifecycle ID: `io-7426b49dc042`
- 이슈: https://github.com/m16khb-org/issueops/issues/560
- 브랜치: `560-remove-orca-integration` (base `main`, 봉인 SHA `bac123aa`)
- 사용자 요청 범위: 1·2·3단계(기본 경로에서 Orca 제거, Orca 모드 코드 삭제, 계약 정리). 4단계(cmux 제거)는 범위 밖이다.
- 사용자 추가 지시(계획 단계 중): "관련된 legacy도 남기지 말고 깔끔하게 제거", 이어서 "정리없이 코드만 제거하자 그런것들은 그때가서 다시 작업하자". 그래서 Orca와 실행 방식 선택에 딸린 호환 경로를 코드에 남기지 않는다. 로컬 state의 옛 모양 데이터는 이번 작업에서 정리하지 않는다.
- 승인된 종료점: draft PR 발행과 `execution complete`. merge와 cleanup은 별도 승인 단계다.
- 세션 인계: `execution prepare` 뒤 IssueOps 라우터의 환경별 자동 세션 인계를 적용한다. 자동 인계는 위 범위를 넓히지 않는다.

## 목표

실행 방식 개념을 없애고 direct 경로 하나만 남긴다. Orca 관련 코드·계약·문서와, 실행 방식 선택에 딸린 기록 필드·호환 읽기 경로를 모두 지운다. 구현 세션 인계는 Herdr 또는 사용자가 연 두 번째 터미널에서 기존 인수 체인(`release` 뒤 새 세션의 `replace --preview`, `--reseed`, `claim --claim-current-token`)으로 한다.

## 확정한 설계 결정

1. **기록 모양.** 실행 방식이 하나뿐이므로 방식을 기록하는 필드를 모두 지운다.
   - `Execution.Mode`와 `ExecutionMode` 타입, `ExecutionModeDirect`·`ExecutionModeOrca` 상수(`internal/contract/issueops/execution.go:8-13,25`)와 lease 쪽 사본(`internal/contract/issueopslease/record.go:68`).
   - `Execution.Selection`과 `ExecutionSelection`(requested/resolved mode, probe, fallback, readiness fingerprint, explicit direct reason)과 lease 쪽 `Selection`.
   - `Workspace.Driver`(값이 `git` 하나로 강제됨: `internal/domain/issueopslease/record_validation.go:36`)와 그 값을 채우던 `port.ExecutionWorkspaceReceipt.Driver`(`internal/port/execution_workspace.go:25`, 채움: `internal/adapter/gitworktree/provisioner.go:79`).
   - `Execution.Orca`와 `OrcaBinding`, `OrcaArtifactIdentityVersion`.
   - 이 필드를 투영하던 표면: inventory `mode`(`internal/contract/issueopsinventory/types.go:29`), owner context·claim context의 `mode`(`internal/contract/issueops/owner_context.go:32`, `internal/contract/issueopslease/claim_context.go:6`), 실행 API 결과의 `mode`·`resolved_mode`(`internal/contract/issueops/execution_api_types.go`, `execution_action_types.go`, `internal/contract/issueopspreparation/prepare.go:30`), 실행 요청의 `ExecutionPrepareRequest.Mode`(`internal/contract/issueops/execution_api_types.go:110`), operational health snapshot의 실행 방식 필드(`internal/contract/operationalhealth/types.go:32`). 같은 파일의 sync-base `mode`(apply|finalize, `internal/contract/issueops/execution.go:154`, `execution_api_types.go:209,226`)는 실행 방식과 무관하므로 남긴다.
   - 해당 필드의 읽기 검증(`internal/domain/issueops/execution_validation.go`, `internal/domain/issueopslease/record_validation.go`의 mode·selection·driver·orca 규칙)도 지운다. schema_version은 1로 둔다(2026-10-07 ADR이 필드를 지울 때 버전을 올리지 않은 선례를 따른다).
2. **옛 데이터.** 정리하지 않는다. 기록 디코더 세 곳이 `DisallowUnknownFields`를 쓰므로(`internal/contract/issueopslease/record.go:132-133`, `internal/adapter/issueops/issueops_state.go:66-67`, `internal/adapter/outbound/issueopsrecord/codec.go:28-29`) 옛 바이너리가 쓴 실행 기록(`mode`·`selection`·`driver` 포함, 이 기기에 18개이며 이 사이클도 prepare 뒤 포함된다)은 새 바이너리에서 일반 `invalid state`로 읽히지 않는다. 그 기록은 `status`뿐 아니라 `cleanup finish`·`cleanup abandon`도 할 수 없다(abandon도 엄격한 디코더로 읽는다: `internal/adapter/issueops/cleanup_records.go:32`). 인계 감사 파일은 lifecycle과 무관하게 영향을 준다. 감사 파일 전체 읽기(`Read` = `ReadFor("", "")`, `internal/adapter/audit/handoff_delivery.go:93-94`)는 파일 어디든 검증에 실패한 줄이 하나만 있어도 실패하고(`:139-141,167-169`), 이 기기 감사 파일 104줄 중 86줄이 orca launcher다. 그래서 감사 파일을 정리하기 전까지 이 기기에서는 모든 사이클의 `execution handoff-cmux`가 외부 호출 전에 실패하고(`issueops_cmux_wiring.go:65` → `issueopscmux/service.go:85`), 모든 direct claim에서 manual owner claim 관측이 조용히 빠진다(`handoffdelivery/service.go:43-44`, 오류는 `issueops_claim_wiring.go:49`에서 버려져 claim 자체는 성공한다). 사용자 지시대로 이 데이터 정리는 후속 작업으로 남기고, 새 ADR과 PR 본문에 영향과 범위를 적는다. 호환 읽기, skip 규칙, 마이그레이션 명령을 만들지 않는다.
3. **이 사이클의 바이너리 경계.** PATH의 `issueops`는 source checkout의 `bin/issueops`를 가리킨다(`~/.local/bin/issueops` symlink). 이 사이클의 기록은 옛 바이너리가 쓴 모양이므로, merge 전까지 lifecycle 명령(`next`, `status`, phase 전이, 증거 기록, `remote`, `execution complete`)은 PATH의 `issueops`로만 실행한다. worktree에서 빌드한 `./bin/issueops`는 테스트·smoke·게이트에만 쓰고 실제 user state를 가리키는 명령에는 쓰지 않는다. source checkout의 `bin/issueops`를 다시 빌드하거나 `issueops update`를 실행하지 않는다. merge 뒤 이 사이클과 이 기기의 기존 사이클은 바이너리를 갱신하기 전에 옛 바이너리로 정리해야 한다(PR 단계를 지난 사이클은 `cleanup finish`, 그 전 단계 사이클은 끝까지 진행하거나 `cleanup abandon`). 그 순서는 merge·cleanup 승인 단계에서 다룬다.
4. **`execution prepare` 표면.** `--mode`, `--direct-reason`, `--owner-host`, `--owner-model`, `--owner-effort`, `--issue-snapshot-file`, `--expected-readiness-fingerprint`를 지운다. 새 형태는 `execution prepare --id ID ACTOR_FLAGS [--confirm] [--json]`이다. 실행 방식 결정 행렬과 그 fingerprint·selection receipt(`internal/domain/issueopspreparation/decision.go`의 `Decide` 방식 분기, `Fingerprint`, `ValidateSelectionReceipt`, `NormalizeMode`, `NormalizeDirectReason`, `OrcaReadiness`, `CodePreviewOrca/ApplyOrca`)를 지운다. 기존 execution 판정(`existing`, `pending_reconcile`, writerless)처럼 direct가 쓰는 판정만 남긴다. preview는 workspace root·branch·base를 보여 주고 confirm이 만든다(`prepareDirect`, `internal/application/issueopspreparation/prepare.go:368-426`).
5. **`execution claim`·`replace`·`reconcile`.** claim에서 `--issue-body-sha256`, `--context-packet-sha256`, `--issue-snapshot-file`을 지운다. 봉인 claim context는 Orca에서만 요구됐다(`internal/domain/issueopslease/claim_context.go:12-13`, `internal/application/issueopslease/claim_context.go:34-36`). replace·reconcile의 `--issue-snapshot-file`도 Orca 분기에서만 읽혔다(`internal/domain/issueops/execution_issue_snapshot.go:40-41`, `internal/adapter/outbound/issueopslease/reseed_artifacts.go:56-60`). `--claim-current-token`과 token 검증은 유지한다.
6. **삭제하는 명령.** `execution resume`, `execution switch-mode`. MCP `issueops_execution`의 `resume` action과 Orca·방식 선택 property도 지운다. `domain/commandparse`의 `TestRemovedExecutionCommandsHaveNoFlagSpecs` 목록에 두 명령을 더한다.
7. **pending intent.** `Execution.Pending`, `external_intent_v1` bucket, `remote_pr_create` 경로는 유지한다(`internal/contract/issueopspublication/intent.go:3`). Orca kind(`worktree_create`, `owner_launch`, `dispatch`), Orca intent stage 체인, reconcile의 `RouteOrca`·`SkipMutationGuard`를 지운다.
8. **`issueops next`와 writerless 복구.** `RecoveryResume`과 Orca 분기를 지운다. claimable은 `claim --claim-current-token`, released는 `replace --preview`, revoking은 `replace --finalize-preview`로 안내한다(`internal/domain/issueopslease/writerless_recovery.go`). `plan.handoff`의 next_command는 `issueops execution prepare --id ID $ACTOR_FLAGS --json`이다. `internal/domain/issueopsnext/owner_command.go:91`의 옛 prepare 플래그도 고친다.
9. **replacement.** quiescence와 inventory fingerprint에서 Orca owner inventory, runtime rollover, owner 재봉인을 지운다. workspace 프로세스 정지 확인(`requireQuiescentWorkspaceProcesses`)과 holder 프로세스 `dead` 요구는 그대로 둔다.
10. **artifact stage.** `CanStage`는 execution이 생기기 전에만 허용한다(`internal/domain/issueopsartifact/artifact.go:34-47`의 released Orca generation 예외 삭제).
11. **cleanup.** finish의 `orca_remove` 단계와 실패 단계 값, abandon의 `orca_resources_absent` 게이트, inventory의 Orca 필드, Orca 터미널 환경 변수 처리를 지운다. 워크트리 프로세스 정지(`workspace_processes_stop`)는 유지한다.
12. **doctor.** operational health에서 Orca 수집기·분류 어휘, 실행 방식 기반 판정, `--preserve-terminal`, `interactive` profile을 지운다(profile은 Orca 탭 때문에만 존재: `internal/contract/operationalhealth/types.go:175-180`). 사이클 생존 판정은 holder 식별자로만 한다. `--preserve-cycle`은 유지한다.
13. **인계 기록.** handoff-delivery launcher에서 `orca`와 `orca_dispatch*` evidence를 지우고 `direct`·`herdr`·`cmux`를 남긴다. Orca 같은 세대 상관 규칙을 지우고 manual-direct 관측(source generation N과 claim N+1 연결)은 유지한다. `application/handoffdelivery/provisioner*.go`(Orca provisioner wrapper)를 지운다. 지원하지 않는 launcher 줄을 건너뛰는 규칙은 만들지 않는다(결정 2).
14. **owner 프롬프트·packet.** Orca owner 프롬프트 템플릿(`internal/adapter/issueops/testdata/execution_owner_prompt.txt`, embed: `internal/adapter/issueops/execution_owner_context.go:16-19`)과 렌더러(`internal/application/issueopsowner/service.go:70` `RenderOwnerPrompt`), owner context packet, 이와 byte parity로 묶인 `.issueops/prompt-engineering/prompts/issueops-v1-owner-execution-v1.md`를 지운다. 구현 전에 소비자가 Orca prepare·reseal·resume뿐임을 확인한다. direct가 쓰는 소비자가 있으면 그 부분만 남기고 Orca 문장을 뺀다. direct가 쓰는 artifact 봉인(`MaterializeDirect`, `materializeStagedArtifacts`)은 유지한다.
15. **제3자 hook fixture.** `internal/adapter/{claude,codex,installutil}` 테스트와 `internal/adapter/verification/probe/nativeintegration/validation_native_integration_test.go:239-246`의 `orca` 문자열은 다른 도구의 hook 묶음을 보존하는지 보는 fixture다. 동작은 그대로 두고 fixture 이름만 중립 이름(`acme`)으로 바꾼다.
16. **부분 문자열 이름 변경.** 성공 기준 1은 대소문자를 무시한 `orca` 부분 문자열 검사다. Orca와 무관한 이름이 걸리는 18개 파일의 이름을 바꾼다. production: `prepareInstallPathPlanForCandidate`(`cmd/issueops/installcli/install_native_path.go`, `install_transaction_effects.go`)를 `prepareInstallPathPlanFromCandidate`로, `isErrorCamel`(`internal/adapter/inspect/receipts.go`)를 `isCamelCaseError`로. 테스트 이름 `TestBaseSyncRequiredErrorCarriesReseedFreeNextCommand`는 `internal/adapter/augmentation/signals.go`가 파일 내용으로 찾으므로 테스트(`internal/contract/issueops/execution_sync_base_test.go`), `signals.go`, `cmd/issueops/selfworkflow/augmentcatalog/self_augment_repo_signals_test.go`를 같은 커밋에서 `TestBaseSyncRequiredErrorKeepsReseedFreeNextCommand`로 바꾼다. 나머지 테스트 전용 이름(`collectorCalls`, `inspectorCalls`, `sourceHasSelectorCall`, `HonorCanceled`·`HonorCancellation`, `ExecutorCapture`, `ExecutorCancelled`·`ExecutorCancellation`·`ForCancelled`, `ActorCanonicalizes`)도 바꾼다. `ExecutionMode` 식별자를 지우는 G4에 걸리는 테스트 이름 `TestImplementationReviewMissingAppliesToEveryExecutionMode`(`internal/adapter/issueops/issueops_implementation_review_test.go:72`)도 본문과 함께 다시 쓴다. 바꾼 뒤 옛 이름을 저장소 전체에서 grep해 남은 참조를 고친다.
17. **지운 이름 잔여 검사.** 지운 명령·플래그·필드 이름으로 현행 표면을 검사한다(게이트 G9). 알려진 잔여: `internal/domain/issueopsnext/owner_command.go:91`, `skills/gitlab-usecase/SKILL.md:40-44`(`issue_snapshot`, `--issue-snapshot-file`), `.issueops/SUB_AGENT_PATTERNS.md:65`(`execution resume`), 결정 14의 prompt-engineering 문서.
18. **cmux.** `execution handoff-cmux`와 `application/issueopscmux`는 그대로 둔다. cmux 검증의 "released direct execution" 조건(`internal/domain/issueops/cmux_handoff.go:72`)은 mode 비교만 지우고 released·generation 조건은 유지한다. 단 결정 2에 따라 감사 파일을 정리하기 전까지 이 기기에서는 cmux 인계가 실패한다. 코드 경로는 유지되고, 감사 파일을 정리한 기기나 새 state에서는 동작한다(G6·G7의 cmux 테스트는 임시 state에서 돈다).

## 성능 영향

hot path가 아니다. 바뀌는 경로는 CLI 한 번마다 도는 prepare·claim·replace·cleanup·doctor이며, Orca RPC와 Orca inventory 조회가 사라져 외부 프로세스 호출이 줄어든다. 복잡도 변화는 없다. 별도 측정 계획은 두지 않고 바이너리 크기와 삭제 줄 수만 결과 보고에 숫자로 남긴다.

## 하위 호환성과 side effect

- **CLI 계약**: `execution resume`, `execution switch-mode` 삭제. `execution prepare`·`claim`·`replace`·`reconcile`의 Orca·방식 선택 플래그 삭제. `doctor --preserve-terminal` 삭제. 지운 플래그를 넘기면 표준 `flag provided but not defined` 오류가 난다.
- **CLI·MCP JSON 출력**: `execution prepare`·`status`·`list`·`next` 등의 결과에서 `mode`·`resolved_mode`·`selection`·`driver`·Orca 필드가 사라진다. `mcp_tools.golden.json`, usage golden, response contract golden, compatibility contract hash가 바뀐다.
- **record schema**: `execution.mode`, `execution.selection`, `execution.workspace.driver`, `execution.orca`, `orca_*` cleanup inventory 필드, `orca_remove` 실패 단계 값이 사라진다. 옛 바이너리가 쓴 실행 기록은 새 바이너리에서 `invalid state`다(결정 2). 이 기기에서는 실행이 있는 기록 18개가 해당한다(이 사이클 포함). 데이터 정리는 후속 작업이다.
- **감사 파일**: 형식과 digest 규칙은 바뀌지 않는다. 옛 orca 줄이 하나라도 남은 감사 파일에서는 전체 읽기가 실패해 이 기기의 모든 사이클에서 cmux 인계가 막히고 manual claim 관측이 빠진다(결정 2).
- **fingerprint**: replacement inventory·quiescence, cleanup inventory fingerprint 입력이 바뀐다. 업데이트 직후 진행 중인 replace·cleanup은 preview부터 다시 받는다.
- **롤백**: PR을 되돌린 옛 바이너리는 새 바이너리가 쓴 실행 기록을 읽지 못한다(옛 검증기는 `mode`·`selection`·`driver`를 요구한다). 옛 바이너리는 새 사이클을 읽지도 abandon하지도 못한다(`cleanup abandon`도 같은 디코더로 읽는다). 이 기록도 후속 데이터 정리 범위이며 새 ADR에 적는다.
- **이 사이클**: 결정 3의 바이너리 경계를 지킨다.
- **스킬·문서**: 스킬 계약 테스트(`internal/adapter/issueops/issueops_skill_contract_test.go`)가 Orca 문구를 고정하므로 스킬과 같은 커밋에서 기대 문구를 바꾼다. Herdr 우선과 cmux 명시 선택 규칙은 유지한다.
- **저장소 밖 호출자**: 저장소 밖 스크립트나 전역 스킬이 `--mode direct --direct-reason`, `execution resume`을 부르면 업데이트 직후 실패한다. 새 ADR과 PR 본문에 바뀐 명령 형태를 적는다.
- **외부 상태**: 사용자 머신의 Orca 리소스와 저장소 밖 전역 스킬은 건드리지 않는다.
- **프롬프트 변경**: Orca owner 프롬프트 템플릿을 지운다(결정 14). Herdr·cmux 인계문은 Orca 문장만 빼고 의미를 바꾸지 않는다. 실패 기준: 인계문에 `orca`·`resume` 지시가 남거나 released 인수 체인 안내가 빠지면 실패다. G2와 session-choice의 인수 체인 문장으로 확인한다.
